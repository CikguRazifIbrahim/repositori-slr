# Repositori SLR

Aplikasi web boleh pasang (PWA) untuk merekod 13 medan ekstrak bagi setiap artikel jurnal, menyimpan PDF dalam Google Drive dan menyegerakkan rekod ke semua peranti (Windows, Android, pelayar).

Rekod disimpan dalam **Firestore** (projek Firebase sendiri, percuma, sokongan luar talian). Fail PDF disimpan dalam folder **"Repositori SLR"** di **Google Drive** akaun sendiri (percuma, 15 GB). Kod aplikasi dihoskan di **GitHub Pages**.

## Persediaan sekali sahaja

Semua langkah di bawah dibuat dalam pelayar pada komputer. Anggaran masa: 20 minit.

### A. Firebase (Firestore dan log masuk)

1. Buka https://console.firebase.google.com dan pilih projek sedia ada (contoh: projek MyKajian) atau cipta projek baharu.
2. **Authentication > Sign-in method**: pastikan **Email/Password** diaktifkan. Pada tab **Users**, pastikan akaun e-mel pemilik wujud (tambah jika belum).
3. **Authentication > Settings > Authorized domains**: tambah domain GitHub Pages, contohnya `cikgurazifibrahim.github.io`.
4. **Firestore Database**: jika belum ada, klik **Create database** (mod *production*, lokasi `asia-southeast1`).
5. **Firestore Database > Rules**: gantikan peraturan dengan blok berikut (atau tambah koleksi `teks` dan `cadangan` jika blok `artikel` dan `meta` sudah ada), kemudian **Publish**. Gantikan e-mel dengan e-mel pemilik.

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       function pemilik() { return request.auth != null && request.auth.token.email == "saya@cikgurazif.com"; }
       match /artikel/{id} { allow read, write: if pemilik(); }
       match /meta/{id} { allow read, write: if pemilik(); }
       match /teks/{id} { allow read, write: if pemilik(); }
       match /cadangan/{id} { allow read, write: if pemilik(); }
       match /users/{uid}/{document=**} { allow read, write: if request.auth != null && request.auth.uid == uid; }
     }
   }
   ```

   Koleksi `teks` menyimpan ayat yang diekstrak daripada PDF (Peta Ayat) dan `cadangan` menyimpan tiga artikel harian. Tanpa dua baris itu, kedua-dua ciri berfungsi pada satu peranti sahaja (disimpan setempat) dan aplikasi memaparkan amaran.

6. **Project settings (ikon gear) > General > Your apps**: pilih aplikasi web (ikon `</>`) atau cipta satu, kemudian salin objek `firebaseConfig` (apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId).

### B. Google Cloud (akses Google Drive)

Projek Firebase ialah projek Google Cloud yang sama. Buka https://console.cloud.google.com dan pilih projek itu di bahagian atas.

1. **APIs & Services > Library**: cari **Google Drive API** dan klik **Enable**.
2. **APIs & Services > OAuth consent screen** (atau **Google Auth Platform > Branding**):
   - App name: `Repositori SLR`; User support email dan Developer contact: e-mel sendiri.
   - **Audience**: External. Selepas disimpan, klik **Publish app** supaya statusnya *In production* (tanpa langkah ini, kebenaran tamat setiap 7 hari).
   - **Data access / Scopes**: tambah skop `https://www.googleapis.com/auth/drive.file` (skop bukan sensitif, tidak memerlukan pengesahan Google).
3. **APIs & Services > Credentials > Create credentials > OAuth client ID**:
   - Application type: **Web application**; Name: `Repositori SLR Web`.
   - **Authorized JavaScript origins**: `https://cikgurazifibrahim.github.io` (tanpa laluan, tanpa garis miring di hujung).
   - **Authorized redirect URIs**: `https://cikgurazifibrahim.github.io/repositori-slr/` (dengan garis miring di hujung). Ini membolehkan "Sambung Drive (cara lencongan)" apabila tetingkap kebenaran Google disekat dalam aplikasi yang dipasang.
   - Klik **Create** dan salin **Client ID** (berakhir dengan `.apps.googleusercontent.com`).

### C. Masukkan nilai ke dalam `config.js`

Buka fail `config.js` dalam repo ini (boleh diedit terus di GitHub: klik fail, ikon pensel, edit, *Commit changes*). Gantikan setiap nilai yang bermula dengan `ISI_`:

- `firebase.*` daripada langkah A6
- `googleClientId` daripada langkah B3
- `ownerEmail` ialah e-mel akaun log masuk (mesti sama dengan e-mel dalam peraturan Firestore)

GitHub Pages menerbitkan semula secara automatik dalam satu hingga dua minit.

### D. Pasang sebagai aplikasi

- **Windows (Chrome atau Edge)**: buka alamat aplikasi, klik ikon *Install* di hujung bar alamat, atau menu tiga titik > *Cast, save and share* > *Install page as app*. Aplikasi muncul di menu Start.
- **Android (Chrome)**: buka alamat aplikasi, menu tiga titik > *Add to Home screen* > *Install*. Aplikasi muncul di skrin utama dan dibuka tanpa bar pelayar.

Kali pertama memuat naik PDF pada setiap peranti, Google akan meminta kebenaran akses Drive sekali.

Token Drive tamat kira-kira sejam selepas disambung. Cip "Drive disambung" bertukar kepada **Sambung Drive** apabila token tamat (disemak setiap 30 saat dan apabila tab kembali aktif). Jika token tamat atau ditolak ketika muat naik sedang berjalan, aplikasi tidak lagi cuba membuka tetingkap kebenaran secara automatik (pelayar menyekat tetingkap yang dibuka tanpa klik pengguna, lalu muat naik gagal dengan "tetingkap kebenaran Google disekat"); sebaliknya fail yang belum selesai disimpan sebagai tertangguh dan butang **Sambung Drive dan teruskan** (pada baris log muat naik, pada pemberitahuan, dan melalui cip Sambung Drive) menyambung semula dalam klik pengguna lalu meneruskan muat naik fail yang sama tanpa perlu dipilih semula. Jika tetingkap kebenaran tidak muncul dalam aplikasi yang dipasang (biasa berlaku pada Windows apabila pop-up disekat), buka menu tiga titik dan pilih **Sambung Drive (cara lencongan)**. Aplikasi beralih ke halaman Google, kemudian kembali dengan token. Menu **Diagnostik Drive** menunjukkan punca sebenar sebarang kegagalan dan nilai yang mesti didaftar dalam Google Cloud.

## Ciri utama

- **Papan**: senarai artikel dengan tapisan, statistik, muat naik PDF (seret dan lepas), butang **Baca** (flipbook terapung) dan **Muat turun** bagi artikel yang belum selesai dibaca (paparan Senarai). Paparan lalai ialah **Kumpulan label** (`mod/kumpulan.js`): artikel dikelompokkan mengikut label, iaitu Tema utama rekod, dengan susunan Kepimpinan Digital, Pengurusan Pengetahuan Organisasi, Kompetensi Digital Guru, kemudian Lain-lain; artikel yang belum dilabel diletakkan paling atas dengan cip label pantas (KD, PPO, KDG, Lain) dan **cadangan automatik** (peraturan istilah pada tajuk, objektif, konstruk dan subtopik serta jiran terdekat TF-IDF dalam kalangan artikel yang sudah dilabel, dengan sebab yang dipaparkan; butang "Terima cadangan yang pasti" melabel semuanya sekali gus selepas pengesahan). Dalam setiap kumpulan, artikel Selesai di atas, kemudian Sedang dibaca dan Belum dibaca, dengan pilihan Susun sebagai urutan kedua; kepala kumpulan menunjukkan bilangan mengikut status, melekat ketika menatal dan boleh dilipat (diingat pada peranti); baris dipaparkan padat (Bil., penulis, status, tajuk satu baris, relevansi, PDF, tarikh) tanpa butang Baca dan Muat turun; tiada ketinggian tetap bagi kumpulan. Pilihan Paparan (Kumpulan label atau Senarai) disimpan pada peranti; tapisan dan carian terpakai kepada kedua-dua paparan. Pilihan **Susun** merangkumi **Tarikh muat naik, terbaharu dahulu** dan **Tarikh muat naik, terlama dahulu** (mengikut masa fail PDF terbaharu rekod itu dimuat naik ke Drive, `fail[].masa`; rekod tanpa PDF mengikut masa rekod dicipta). Dalam paparan Kumpulan label, kumpulan pemboleh ubah kekal dan susunan tarikh berlaku di dalam setiap kumpulan sebagai urutan tarikh tulen (hari ini, semalam, dan seterusnya; status bacaan tidak didahulukan bagi dua susunan ini, berbeza daripada susunan lain yang mendahulukan Selesai). Tapisan **Dimuat naik** menapis mengikut masa yang sama: julat (hari ini, 3, 7, 14, 30 atau 90 hari lepas) atau satu tarikh tertentu daripada **kalendar muat naik** (`mod/kalendar.js`) di bawah pilihan itu: kalendar bulanan kecil menandakan hari yang ada muat naik dengan bilangan artikel, hari ini bergaris, hari akan datang dilumpuhkan, anak panah menukar bulan dan "Hari ini" kembali ke bulan semasa; klik satu hari untuk melihat artikel hari itu sahaja (kumpulan pemboleh ubah dan susunan kekal, pilihan "Pada <tarikh>" muncul dalam senarai juntai), klik hari yang sama atau "Buka semula" untuk membukanya. Apabila susunan atau tapisan muat naik aktif, tarikh pada setiap baris (kedua-dua paparan) menunjukkan "Dimuat naik" atau "Dicipta" dan bukannya masa kemas kini, dan nota di bawah kepala senarai menerangkan urutan atau tarikh yang sedang dipakai. Eksport CSV mempunyai lajur Dimuat naik. Semua senarai juntai artikel (Artikel 1 dan Artikel 2 dalam Banding, artikel sumber dan pasangan soal jawab dalam Artikel, Tambah hubungan dalam medan 12) menggunakan pembina yang sama (`Kumpulan.pilihanHtml`): dikelompokkan mengikut pemboleh ubah (KD, PPO, KDG, Lain, kemudian Belum dilabel) dengan bilangan mengikut status pada kepala kumpulan, Selesai dahulu dalam setiap kumpulan, dan setiap baris membawa tanda status, Bil., penulis, tahun, kelengkapan A hingga F dan tajuk.
- **Rekod**: 13 medan ekstrak, pemapar PDF skrin penuh atau bersebelahan borang, flipbook, muat turun, dan **Indeks ayat** untuk Peta Ayat. Kotak teks Kekuatan dan Kelemahan (medan 10) selebar borang dan disusun menegak, sama seperti kotak Jurang, supaya ayat tidak terpenggal; setiap kotak teks boleh dibesarkan dengan menyeret penjuru kanan bawah. **Rantaian sintesis** (medan 12 Bandingan silang, `mod/sintesis.js`): di bawah teks bebas medan 12, setiap rekod menyimpan senarai `hubungan` berstruktur dengan artikel lain dalam repositori (jenis: selari, bercanggah, melanjutkan, melengkapi, mengulang, berbeza konteks; aspek: teori, konstruk, kaedah, instrumen, sampel dan konteks, dapatan, jurang, implikasi; nota satu atau dua ayat). Hubungan ditulis sekali dan dipaparkan dua hala ("Dirujuk oleh" dalam rekod artikel itu, dengan butang Balas hubungan); setiap baris mempunyai **Ringkasan kilat** (objektif, konstruk, teori, kaedah, instrumen, dapatan, jurang, relevansi artikel itu) supaya artikel yang sudah lama dibaca diingat semula tanpa membukanya, serta butang Buka rekod dan Banding. **Mungkin berkaitan** mencadangkan artikel lain secara automatik daripada medan (tema sama, teori sepunya yang dikesan daripada medan teori, definisi, konstruk dan instrumen, reka bentuk, kesan perantaraan, peringkat, negara, asas teori, subtopik, dan istilah sepunya TF-IDF) dengan sebab yang telus dan skor. **Rangka sintesis** menyusun semua hubungan rekod itu (termasuk yang masuk) menjadi perenggan rangka deterministik tanpa token, yang boleh dimasukkan ke hujung medan 12; **Peta sintesis** memaparkan kelompok artikel yang saling berkait dalam seluruh repositori (tapis aspek dan jenis, Rangka kelompok, eksport CSV). Eksport CSV utama mempunyai lajur Hubungan sintesis.
- **Mohon Prof Dr Claude isikan**: butang pada setiap bahagian A hingga F (dan "Isi semua bahagian" di kepala rekod). Aplikasi mengekstrak teks penuh PDF artikel (penanda muka surat [m.s. N]; PDF imbasan tanpa teks dihantar sebagai dokumen, maksimum 100 muka surat), menghantarnya terus dari pelayar ke API Anthropic (Messages API, `https://api.anthropic.com/v1/messages`, pengepala `anthropic-dangerous-direct-browser-access`) dengan kunci API Prof Dr yang disimpan dalam Tetapan, dan mengisi hanya medan yang masih kosong sebagai draf; nilai yang sudah ditulis tidak disentuh. Arahan kepada model: Bahasa Melayu Malaysia akademik, sifar fabrikasi ("Tiada dalam artikel" jika tidak dilaporkan), jejak muka surat bagi angka dan definisi, salin tepat hanya rujukan, statistik dan petikan definisi, pilihan senarai mesti tepat. Jawapan diterima melalui output berstruktur `output_config.format` (`json_schema`): API menjamin jawapan ialah JSON yang sah mengikut satu skema semua medan (skema yang sama bagi setiap bahagian supaya cache prompt kekal sah; 19 medan pendek diwajibkan dengan nilai "-" jika bukan bahagian yang diminta, 22 medan panjang pilihan, mematuhi had API 24 medan pilihan), maka nilai tidak lagi rosak pada tanda petik atau baris baharu seperti teks bebas. `tool_choice` jenis `tool` atau `any` tidak digunakan kerana model keluarga 5.5 menolaknya dengan ralat 400. Jika API menolak skema (ralat 400, tidak dicaj), aplikasi beralih secara automatik kepada alat `isi_medan` dengan `tool_choice` `auto`, kemudian kepada teks JSON biasa, dan mengingati mod yang berjaya bagi model itu. Had token keluaran 8,192; jika jawapan terpotong (`stop_reason: max_tokens`), aplikasi mengulang sekali secara automatik dengan had 16,384 dan arahan meringkaskan (awalan sudah dalam cache, maka ulangan murah). Jika jawapan tiba sebagai teks yang rosak, pembaikan JSON sandaran (pagar kod, tanda petik tidak dilepaskan, baris baharu mentah, koma hujung, kurungan terpotong) dicuba sebelum ralat dilaporkan. Bahagian E dan F merujuk profil kajian Prof Dr (boleh disunting dalam Tetapan) dan bahagian F turut menerima ringkasan artikel lain dalam repositori untuk bandingan silang. Teks artikel dan arahan sistem ditanda `cache_control` supaya bahagian berikutnya artikel yang sama lebih murah. Setiap bahagian yang diisi ditanda "Draf AI" dengan masa, model dan bilangan medan (disimpan dalam medan `aiIsi` rekod). Model: Claude Sonnet 5.5 (lalai), Haiku 5.5 atau Opus 5.5.
- **Hari ini**: tiga artikel sehari daripada OpenAlex, satu bagi setiap pemboleh ubah (Kepimpinan Digital, Pengurusan Pengetahuan Organisasi, Kompetensi Digital Guru). Susunan keutamaan: (1) jenis artikel, iaitu empirikal kuantitatif dahulu (termasuk kaedah campuran, pengesahan instrumen dan eksperimen), kemudian jenis yang tidak dapat dipastikan, kualitatif, ulasan dan konseptual; (2) pengindeksan, iaitu jurnal **Scopus** dahulu (Q1 hingga Q4 mengikut anggaran kuartil SJR, kemudian Scopus tanpa kuartil), diikuti jurnal teras CWTS, kemudian DOAJ, manakala artikel yang tidak dapat disahkan diindeks dan berwasit ditolak; (3) padanan metodologi dengan kajian Prof Dr (tinjauan soal selidik keratan rentas, responden guru sekolah rendah, SEM atau CB-SEM/AMOS, analisis perantara, Malaysia); (4) istilah konstruk dalam tajuk, kuartil, ketersediaan PDF. Jenis dan padanan dikesan automatik daripada tajuk dan abstrak dengan senarai petunjuk yang dipaparkan pada kad (sahkan selepas membaca). Jika kolam empirikal kuantitatif nipis, kueri tambahan dengan istilah metodologi ("structural equation", "survey") dijalankan. Tapisan lain: tahun penerbitan dalam julat lima tahun kalendar terkini, artikel jurnal, akses terbuka, berkonteks pendidikan, bukan TAM atau UTAUT. Carian berjalan automatik sekali sehari apabila aplikasi dibuka (selepas rekod repositori tiba dari pelayan). Setiap kad: **Simpan ke Drive**, Muat turun PDF, Baca di sini, DOI, Semak SJR, Tambah ke repositori (medan Jenis sumber, Reka bentuk, Pengindeksan dan Kuartil diisi awal daripada pengesanan automatik dan dicatat dalam Catatan), Sudah dibaca, Tukar.
- **Banding Artikel** (tab Banding): perbandingan kepala ke kepala dua artikel repositori, seperti perbandingan dua pemain. Pilihan terhad kepada artikel dalam repositori (tiada carian web) dan hanya dua artikel pada satu masa; senarai pilihan dikumpulkan mengikut status bacaan dengan pengepala kumpulan (Selesai dibaca dahulu, kemudian Sedang dibaca dan Belum dibaca, berserta bilangan artikel dan bilangan yang lengkap A hingga F). Perbandingan dibuat hanya jika semua medan Bahagian A hingga F kedua-dua rekod sudah diisi; jika belum, amaran menyenaraikan bahagian dan medan yang kosong berserta butang "Buka rekod" untuk melengkapkannya (sendiri atau dengan "Mohon Prof Dr Claude isikan"), dan pilihan dikekalkan apabila kembali. Tiga lapisan: (1) indeks pantas 0 hingga 100 yang dikira secara telus daripada medan (kekinian, taraf jurnal, kekukuhan kaedah, kekuatan bukti, relevansi, padanan model, asas teori, padanan konteks) dengan carta radar dan bar kepala ke kepala; (2) jadual bersebelahan semua medan A hingga F; (3) Agen Banding Prof Dr Claude, satu panggilan API Anthropic (medan rekod sahaja, bukan PDF, maka kos kecil) yang memulangkan laporan berstruktur: profil ringkas kedua-dua artikel, penilaian teknikal lapan dimensi, persamaan, perbezaan dan penilaian bagi setiap bahagian A hingga F, kekuatan dan kelemahan, laporan keseluruhan ringkas, refleksi perkaitan dengan kajian Prof Dr, cadangan sitasi bersama dan artikel yang lebih berguna berserta sebab. Laporan disimpan dalam `meta/banding_<kunci>` dan salinan tempatan, dimuat semula secara automatik bagi pasangan yang sama (termasuk susunan terbalik), dan boleh disalin atau dimuat turun sebagai Markdown atau, bagi laporan agen sahaja, sebagai **laporan PDF bergrafik** (butang "Muat turun laporan agen (PDF)", muncul apabila laporan agen ada): hanya kandungan yang dijana oleh agen (yang menggunakan token) dimuatkan, manakala indeks pantas dan jadual A hingga F daripada isian pemilik sendiri tidak dimuatkan kerana boleh dibaca semula dalam aplikasi pada bila-bila masa. A4, Liberation Serif dan Liberation Sans terbenam (metrik Times New Roman dan Arial, aksara Yunani dan simbol statistik seperti β dan ≤ dikekalkan), kad pengenalan kedua-dua artikel, profil, penilaian teknikal lapan dimensi sebagai carta radar, purata dan bar bercermin dengan asas skor setiap dimensi, jadual konstruk dan dimensi dengan tanda dimensi dikongsi, perbandingan setiap bahagian, jadual kekuatan dan kelemahan, laporan keseluruhan, refleksi, cadangan sitasi dan kotak keputusan; nombor muka surat, tanda buku seksyen dan pemecahan muka surat yang mengekalkan tajuk bersama kandungannya (blok carta memilih saiz radar mengikut ruang yang tinggal). Dijana sepenuhnya dalam pelayar oleh `mod/laporanpdf.js` dengan jsPDF dan jspdf-autotable (`vendor/laporan.bundle.js`, dimuat hanya apabila butang diklik); warna siri biru (Artikel 1) dan merah jambu tua (Artikel 2) dipilih supaya boleh dibezakan pada kertas putih dan oleh penglihatan warna terhad, dengan poligon Artikel 2 bergaris putus dan berpenanda segi empat. Laporan turut memuatkan **peta dimensi konstruk** setiap artikel (konstruk, peranan bebas, perantara, penyederhana, bersandar atau kawalan, kerangka atau instrumen sumber, dimensi dan subdimensi, dipetakan daripada medan konstruk, definisi, teori dan instrumen) dengan dimensi yang dikongsi ditanda, serta perbandingan dimensi (persamaan, perbezaan, implikasi kepada instrumen Prof Dr); peta setiap artikel disimpan dalam rekodnya (`petaDimensi`). **Kayu ukur**: satu artikel boleh ditetapkan sebagai penanda aras (`meta/banding_kayu` dan tempatan); ia kekal sebagai Artikel 1, butang "Artikel seterusnya" menggilirkan artikel lengkap yang belum dibandingkan, dan senarai pasangan tersimpan dengan kayu ukur boleh dibuka semula. **Pola merentas artikel**: matriks semua artikel berpeta (kayu ukur dahulu) mengikut peranan konstruk dengan kerangka dan dimensi, dimensi yang sama dengan kayu ukur ditanda hijau, padanan Jaccard dalam peratus, kekerapan dimensi dan kerangka merentas artikel, butang "Jana peta dimensi" bagi artikel yang belum berpeta (panggilan agen ringan daripada medan rekod) dan eksport CSV.
- **Tulisan Tesis** (tab Tulisan): buku nota penulisan Bab 1 hingga Bab 5 di dalam sistem supaya tiada perenggan yang hilang atau ditaip dua kali. Setiap bab mengandungi seksyen (tajuk dan kandungan). Setiap seksyen mempunyai **dua pane bersebelahan**: **ASAL** di kiri ialah teks akhir seksyen (yang masuk ke Word, kiraan patah, carian dan Semalam), **RAM** di kanan ialah kanvas sementara bahan mentah bagi seksyen yang sama (medan `ram`, disimpan dan disegerakkan seperti ASAL tetapi tidak dieksport ke Word; ditanda "RAM" dalam senarai seksyen dan turut dicari). Kedua-dua pane berkongsi bar alat yang sama; "Muat naik Word ke RAM" (hanya pada RAM) memasukkan keseluruhan fail .docx ke RAM (ganti atau tambah), "Pindah ke RAM" dan "Pindah ke ASAL" menggerakkan teks yang dipilih (seret), atau blok di kursor (perenggan, jadual, senarai) jika tiada pilihan, atau keseluruhan RAM jika tiada kursor dalam RAM; dalam sasaran, satu perenggan masuk sebaris pada kursor terakhir (dengan ruang ditambah jika perlu) manakala blok masuk selepas blok di kursor atau di hujung; seret dan lepas serta salin dan tampal antara kedua-dua pane juga berfungsi; "Kosongkan RAM" membuang kandungan RAM selepas pengesahan; Gabung menggabungkan ASAL dan RAM kedua-dua seksyen. Paparan Tulisan menggunakan lebar penuh dengan jidar 8 px dan senarai seksyen 250 px; pane disusun menegak pada skrin sempit. **Editor teks kaya** seperti Word: tebal, condong, garis bawah, superskrip dan subskrip, **warna teks** untuk melabel kepentingan (palet enam warna sederhana: merah, biru, hijau, oren, ungu, kelabu, serta Asal untuk membuang warna; pilih teks kemudian klik warna; disimpan sebagai kelas `w-<nama>` dengan tona terang dan gelap mengikut tema, dieksport sebagai warna run dalam Word, dan dibaca semula daripada fail Word dengan membaca `word/document.xml` (JSZip) lalu menjajarkan run berwarna dengan teks HTML mammoth aksara demi aksara; warna Word dipadankan ke warna palet terdekat, hitam dan kelabu gelap dianggap tanpa warna), senarai berbutir dan bernombor, jadual (sisip dengan bilangan baris dan lajur, tambah atau padam baris dan lajur, baris kepala, Tab berpindah sel) dan rajah (fail imej dikecilkan kepada sisi terpanjang 1,600 px dan 600 KB, disimpan dalam dokumen Firestore sendiri `meta/tulisan_imej_<id>` dan dirujuk melalui `data-imej` supaya dokumen bab kekal di bawah had 1 MiB); teks yang ditampal daripada Word mengekalkan format (HTML disaring kepada tag yang dibenarkan sahaja; gaya, kelas dan skrip dibuang; imej daripada papan keratan Word tidak dapat dibaca dan perlu disisip melalui butang Rajah); muat naik Word peringkat seksyen (jadual dan rajah termasuk, tajuk di dalam fail menjadi perenggan tebal) masuk ke RAM seperti di atas; "Salin" menyalin seksyen dengan format ke papan keratan. Setiap seksyen menyimpan `html` (teks biasa `teks` diterbitkan semula ketika dimuatkan dan disimpan sebagai `null` dalam awan supaya saiz tidak berganda; seksyen lama yang hanya berteks biasa ditukar kepada HTML ketika dipaparkan). Eksport Word menukar HTML kepada perenggan, senarai, jadual (garis tunggal, baris kepala berlorek) dan ImageRun (lebar maksimum 5.7 inci); muat naik Word membaca jadual dan rajah daripada fail. Setiap seksyen disimpan automatik ke awan (`meta/tulisan_b<N>`, gabungan setiap seksyen mengikut masa terbaharu) dan salinan peranti, dan disegerakkan ke semua peranti. Panel "Sambung semula" menyenaraikan seksyen yang terakhir disunting, dan "Apa yang sudah ditulis" merekodkan patah perkataan yang ditulis hari ini, semalam dan tujuh hari terakhir mengikut seksyen; carian merentas semua bab menunjukkan petikan. MS Word ialah pintu masuk dan keluar: "Muat turun fail MS Word" menjana .docx bab (Times New Roman 12, langkau dua, Heading 1 bab, Heading 2 seksyen, inden baris pertama, senarai, jadual dan rajah) dan menandakan bab itu "dipinjam ke Word"; "Muat naik fail MS Word" membaca .docx (mammoth), mengenal pasti bab daripada tajuk "Bab N" atau nama fail, memadankan seksyen mengikut tajuk, menunjukkan pratonton gabungan (Baharu, Dikemas kini, Format sahaja apabila teks sama tetapi warna, tebal atau jadual berbeza, Sama) dengan amaran jika versi dalam sistem disunting selepas fail Word diubah, menyimpan versi lama setiap seksyen yang ditimpa (boleh dipulihkan), membatalkan tanda pinjaman, dan mengarkibkan fail dalam subfolder Tulisan di Google Drive (setiap muat naik dan muat turun). Peringatan dipaparkan ketika log masuk dan dalam tab selagi ada bab yang dipinjam keluar belum dimuat naik semula. Laporan Agen Banding boleh dihantar terus sebagai seksyen baharu Bab 2 ("Tulis ke Tulisan Tesis"). Kedua-dua butang Word turut ada dalam menu tiga titik. Struktur: setiap seksyen mempunyai aras 1 hingga 3 dan nombornya dijana automatik daripada kedudukan dan aras (2.3, 2.3.1, 2.3.1.1; lompatan aras yang tidak sah dipaparkan sebagai aras yang dibenarkan); nombor yang ditaip pada tajuk dibuang automatik. Susun semula dengan seret dan lepas (tetikus: pegang pemegang atau seret item; sentuhan: tekan dan tahan), dengan bingkai bergaris menunjukkan tempat seksyen akan diletakkan dan skrol automatik di hujung senarai; butang Atas dan Bawah dikekalkan. Promosi dan Demosi (anak panah pada setiap item dan butang dalam editor) menukar aras; demosi hanya dibenarkan di bawah seksyen sebelumnya yang arasnya sama atau lebih tinggi. Kali pertama tab dibuka, bab yang belum ada seksyen bertajuk diisi dengan subtopik proposal (Bab 1 hingga 3 mengikut tajuk badan Kertas Cadangan suntingan 27 Ogos 2026 berserta penyusunan semula blok PPDO 28 Ogos 2026; Bab 4 dan 5 cadangan struktur mengikut reka bentuk kajian) sebagai `TEMPLAT` dalam `mod/tulisan.js`; butang "Subtopik proposal" menambah yang belum ada di hujung senarai. Eksport Word memetakan aras kepada Heading 2 hingga 4 dengan nombor; import membaca h2 hingga h4 sebagai aras dan membuang nombor daripada tajuk sebelum dipadankan; seksyen sistem yang masih kosong tidak pernah dianggap lebih baharu daripada fail Word. Panel **Semalam** di bahagian atas tab (jadual Times New Roman 12 pt, merah) menyenaraikan setiap seksyen yang disentuh pada hari terakhir menulis sebelum hari ini (bab, nombor dan tajuk, perubahan patah, patah kini, masa terakhir) dengan tindakan Sambung, Gabung (teks ditambah ke hujung seksyen lain lalu seksyen asal dipadam) dan Padam; log harian merekodkan masa suntingan setiap seksyen walaupun bilangan patah tidak berubah. Teks penuh Kertas Cadangan (27 Ogos 2026) dimasukkan ke Tulisan melalui fail Word yang dijana di luar aplikasi (tidak disimpan dalam repositori ini kerana ia teks peribadi) dan dimuat naik oleh pemilik; dokumen bab yang menghampiri had 1 MiB Firestore dijaga dengan membuang versi lama seksyen (`jagaSaiz`).
- **Artikel Penerbitan** (tab Artikel): ruang menulis artikel jurnal dan persidangan daripada artikel dalam repositori. Setiap artikel penerbitan mempunyai **jenis artikel** (senarai jenis artikel akademik: empirikal, ulasan dan sintesis, konseptual dan teori, metodologi, lain-lain), **artikel sumber** daripada repositori (maksimum 15, dipilih daripada senarai yang dikumpulkan mengikut status bacaan; setiap satu dengan meter kelengkapan Bahagian A hingga F, peratus medan diisi, butang Buka rekod dan Baca), dan **soal jawab merentas semua artikel sumber**: taip soalan (atau klik soalan pantas) dan agen menjawab berdasarkan medan A hingga F semua artikel sumber artikel itu (sehingga 15; blok sumber diletakkan dalam arahan sistem supaya dicache oleh API bagi soalan berturut-turut), ringkasan laporan Agen Banding sedia ada antara sumber (disenaraikan dengan butang ke Banding; sehingga lima dirujuk) dan empat soal jawab terdahulu; agen diarahkan mensintesis merentas semua sumber, menamakan artikel yang menyokong setiap dakwaan, dan mengakhiri dengan perenggan "Untuk artikel Prof Dr". Maksimum 10 soalan bagi setiap artikel; **amaran kos** dipaparkan sebelum setiap soalan dihantar (bilangan sumber, anggaran token masuk, model, baki soalan), setiap satu satu panggilan API dengan kunci API Prof Dr; jawapan disusun mengikut soalan dengan skop dan token setiap satu, dan boleh dipindahkan ke RAM seksyen semasa. Badan artikel ialah seksyen sahaja (tiada Bab 1 hingga Bab 5; butang Seksyen baharu dan Struktur lazim mengikut jenis) dengan editor ASAL dan RAM, warna, jadual, rajah, Word masuk dan keluar, sejarah versi, carian dan panel Semalam yang sama seperti Tulisan Tesis (kilang `initTulisan` yang sama dengan konfigurasi artikel). Simpanan: `meta/penerbitan_indeks` dan `meta/penerbitan_<id>` berserta salinan tempatan.
- **Pandu Tulis** (dalam tab Artikel, di bawah soal jawab): bimbingan menulis artikel langkah demi langkah mengikut **acuan artikel contoh**. Bagi setiap keluarga jenis artikel, satu artikel sebenar yang sudah diterbitkan dalam jurnal berwasit telah dibedah bahagian demi bahagian dan perenggan demi perenggan (fungsi setiap perenggan, cara ia dibina, panjang, bilangan sitasi, nisbah setiap bahagian); angka diukur oleh skrip daripada teks penuh, huraian ditulis dengan kata-kata sendiri dan tiada ayat artikel disalin. Artikel contoh terbina: empirikal kuantitatif, Nadav et al. (2026), https://doi.org/10.1111/ejed.70373; kaedah campuran, Bice dan Tang (2022), https://doi.org/10.1007/s10639-022-11044-1; kualitatif, McLeod dan Dulsky (2021), https://doi.org/10.3389/feduc.2021.637075; pembangunan instrumen, Tzafilkou et al. (2022), https://doi.org/10.1186/s41239-022-00330-0; ulasan skop, Karsikas et al. (2022), https://doi.org/10.1111/jonm.13626; ulasan sistematik, Tummers dan Bakker (2021), https://doi.org/10.3389/fpsyg.2021.722080; meta-analisis, Zeng et al. (2022), https://doi.org/10.3389/fpsyg.2022.1091017; bibliometrik, Rojas-Sánchez et al. (2023), https://doi.org/10.1007/s10639-022-11167-5; ulasan naratif, Timotheou et al. (2023), https://doi.org/10.1007/s10639-022-11431-8; kertas konsep, Ng et al. (2023), https://doi.org/10.1007/s11423-023-10203-6. Apabila acuan aktif: **folder** dan subseksyen mengikut bahagian artikel contoh (Abstrak ditulis paling akhir, Rujukan dijana daripada sitasi), sasaran panjang setiap folder mengikut nisbahnya, kad **Lihat acuan** memaparkan rujukan, sebab dipilih, ukuran dan nasihat penyesuaian, dan bahagian **A** dalam setiap folder memaparkan perbandingan draf dengan artikel contoh, peta perenggan dan **pola ayat** Bahasa Melayu generik. Pemilik boleh **membedah artikel contoh sendiri** daripada repositori (satu panggilan agen membaca teks penuh PDF; disimpan dalam `meta/pandu_acuan_<keluarga>`), atau mematikan acuan. **Jurnal sasaran** lalai ialah berindeks MyCite (boleh ditukar kepada Scopus atau WoS; mempengaruhi piawaian semakan agen dan julat sasaran panjang). Setiap folder melalui lima langkah: (1) artikel panduan utama dan sekunder, (2) soal jawab dengan agen, (3) cadangan penulisan daripada agen, (4) penulisan ASAL oleh pemilik, (5) meter dan semakan agen sebelum ditandakan siap. Semua keluaran agen masuk ke **RAM**; **ASAL** tidak pernah ditulis oleh agen. **Meter** (Panjang, Pemboleh ubah, Sitasi, Padanan acuan, Gerakan retorik, Parafrasa, Gaya) dikira semasa menaip dan dipaparkan di atas editor; amaran muncul sebelum folder ditandakan siap. **Ruang PRISMA 2020** (folder Metodologi dan Dapatan artikel ulasan): pangkalan data, tarikh, rentetan carian penuh dan angka aliran diisi oleh pemilik; sistem mengira kotak yang boleh dikira, menyemak aritmetik, melukis rajah templat rasmi dua lajur (BM atau Inggeris), dan menyisip rajah, jadual strategi carian serta ayat aliran berangka ke RAM atau ASAL, atau memuat turun PNG. **Ruang Output SPSS dan AMOS** (folder Dapatan, Metodologi dan Perbincangan artikel empirikal): jadual ditampal terus daripada SPSS, AMOS atau Excel, rajah dimuat naik atau ditampal; setiap output berlabel dan berkategori dengan senarai semak, boleh disisip ke RAM atau ASAL dengan kapsyen, dihantar kepada agen (teks jadual dan imej), dan meter Angka dan output menyemak angka dalam ASAL terhadap output. Setiap panggilan agen memaparkan anggaran token dan dicaj kepada akaun Anthropic pemilik. Simpanan: `meta/pandu_<id>` (tetapan, peta folder, PRISMA), `meta/pandu_<id>__<folder>` (pilihan sumber, jawapan, log agen), `meta/pandu_<id>__output`, `meta/pandu_gaya` (peraturan gaya), berserta salinan tempatan.
- **DNA jurang** (Pandu Tulis, folder Pendahuluan; v1.25.0): acuan pernyataan masalah yang dikod daripada Pengenalan Luthra et al. (2025), https://doi.org/10.1007/s13198-024-02648-6, bersama skill `dna-pernyataan-masalah`. Jurang dibina berperingkat dalam tiga kitaran (wilayah, jurang, tujuan) dengan 18 kod seni bina (W1 hingga W4, J1, J2, rantaian kritikan K-HASIL, K-ULASAN, K-KONTEKS, K-DIGITAL dan K-PERANAN, rumusan R1 dan R2, T1, T2, I, SK, OK, S, P, O), formula ayat Bahasa Melayu dan Bahasa Inggeris bagi setiap kod, peraturan sitasi Prof Dr, dan senarai kelemahan exemplar yang tidak boleh ditiru. Panel **J** dalam folder Pendahuluan memaparkan **Kad Model** (pemboleh ubah daripada butang Tetapkan, konstruk paksi, peringkat konteks, negara dan perantaraan) dan **Matriks Ketinggalan**: bagi setiap artikel sumber, setiap elemen model ditanda Ada (dikongsi), Tiada (ditinggalkan, iaitu bahan ayat kritikan) atau ?, dianggar tanpa agen daripada medan tajuk, objektif, konstruk, definisi, peringkat, negara dan kesan yang diuji, dan boleh dipinda dengan klik. **Uji Kesatuan** lulus apabila setiap elemen model ditinggalkan oleh sekurang-kurangnya satu kajian empirikal yang layak dikritik dan sekurang-kurangnya tiga kajian layak; ulasan dikira berasingan untuk K-ULASAN. Meter **DNA jurang** dalam Langkah 5 menyemak Uji Kesatuan, bilangan ayat kritikan (sitasi naratif dengan penanda ketinggalan), penanda kontras yang berulang, ayat tujuan bagi setiap kitaran, rumusan sudah dikaji dan belum dikaji, dakwaan negatif mutlak, elemen yang belum disebut dalam ayat kritikan, dan soalan atau objektif perantaraan. Apabila aktif (lalai bagi empirikal kuantitatif dan kaedah campuran; boleh diaktifkan bagi jenis lain), agen Bincang, Cadangan penulisan dan Semakan menerima DNA, Kad Model dan Matriks Ketinggalan; cadangan penulisan melabel setiap perenggan dengan kod DNA dan ditutup dengan perenggan UJI KESATUAN dan NOTA JUJUR. Tetapan disimpan dalam `meta/pandu_<id>` (medan `dna`).
- **Pembantu Tajuk** (dalam tab Artikel, di bawah medan Tajuk artikel): selepas jenis artikel dipilih, pemilik menulis **pembayang tajuk** (teks bebas) dan menjawab **soalan pandu** mengikut jenis artikel (contohnya konsep, populasi dan konteks bagi ulasan skop; pemboleh ubah bebas, bersandar dan pengantara, populasi serta reka bentuk bagi kajian kuantitatif; jurang bagi semua jenis), dengan cip pemboleh ubah daripada tetapan Pandu Tulis serta label dan medan konstruk artikel sumber. Meter kelengkapan pembayang dan amaran timbul menamakan unsur teras yang belum diisi. Agen kemudian mencadangkan **tiga atau lima tajuk** yang berbeza polanya dalam **tetingkap timbul** (satu panggilan API yang kecil dengan amaran kos; yang dihantar hanyalah pembayang, jawapan soalan pandu, tajuk kerja dan senarai ringkas artikel sumber): setiap cadangan memaparkan bilangan patah perkataan, pola, sebab, padanan Bahasa Inggeris (bagi tajuk Bahasa Melayu) dan tanda semakan, dan agen turut bertanya soalan yang boleh menajamkan tajuk. Klik satu cadangan untuk mengisi medan Tajuk artikel; medan itu kekal boleh disunting bila-bila masa, tajuk sebelumnya boleh dipulihkan, dan semua sesi cadangan tersimpan (`meta/tajuk_<id>`) untuk dibuka semula tanpa memanggil agen. Agen tidak pernah mengisi medan Tajuk tanpa klik pemilik. **Semakan tajuk** (tanpa agen, tanpa kos) berjalan setiap kali tajuk berubah: panjang, penanda jenis kajian, pemboleh ubah, singkatan, kata pengisi, gaya, bentuk baku Bahasa Melayu, dan makluman tentang tajuk soalan serta kata sebab-akibat. Peraturan dan pola (`mod/tajuk-data.js`) berasaskan garis panduan pelaporan dan kajian tentang ciri tajuk, setiap satu dengan sumbernya (50 sumber, disahkan pada November 2026 melalui rekod Crossref atau laman rasmi): PRISMA 2020 (https://doi.org/10.1136/bmj.n71) dan PRISMA-ScR (https://doi.org/10.7326/M18-0850) meminta jenis ulasan dinamakan dalam tajuk; piawaian APA bagi kajian kuantitatif, kualitatif, kaedah campuran dan meta-analisis (https://doi.org/10.1037/amp0000191, https://doi.org/10.1037/amp0000151); SRQR, STROBE, CROSS, CONSORT 2025, COSMIN, BIBLIO, RAMESES, PRIOR, PRISMA-P dan Manual JBI; panjang tajuk yang kini lazimnya 11 hingga 15 patah perkataan (Jiang dan Hyland, 2023, https://doi.org/10.1002/leap.1498), dengan purata kira-kira 14 dalam jurnal pendidikan terkemuka (Hyland dan Zou, 2022, https://doi.org/10.1016/j.jeap.2022.101094); bentuk baku Bahasa Melayu daripada Khidmat Nasihat Bahasa Dewan Bahasa dan Pustaka; dan had jurnal Malaysia (Jurnal Pendidikan Malaysia, Akademika, Management Research Journal). Kajian setakat ini tidak membuktikan bahawa mengubah ciri tajuk menaikkan sitasi (Kousha dan Thelwall, 2024, https://doi.org/10.1002/asi.24810), maka peraturan ini bertujuan menjadikan tajuk jelas, mudah ditemui dan selaras dengan garis panduan, bukan menjanjikan sitasi. Medan Tajuk artikel memanjang mengikut panjang tajuk supaya tajuk yang panjang kelihatan sepenuhnya.
- **Sintesis** (tab Sintesis pada reben atas, `mod/bengkel.js` dan `mod/bengkel-data.js`; v1.26.0): ruang berlatih mensintesis ayat daripada beberapa artikel, dibina kerana teguran "penulisan laporan" (ayat artikel A diletakkan di sebelah ayat artikel B tanpa disepadukan). Setiap **kerja sintesis** ialah satu perenggan atau satu idea, dengan dua kanvas bersebelahan seperti menu lain. Kanvas **BAHAN** (kiri) menerima sehingga sepuluh ayat, setiap satu dengan pengarang, tahun dan muka surat (pengarang boleh dipilih daripada rekod repositori; "Tampal banyak ayat" mengesan sitasi di hujung atau di pangkal perenggan; "Isi daripada rekod" memasukkan medan Dapatan, Definisi, Jurang dan lain-lain daripada rekod yang sepadan; "Tambah dapatan saya" bagi perbincangan Bab 5). Semakan kesesuaian awal berjalan tanpa token: sekurang-kurangnya dua sumber berlainan, ayat tanpa sumber, ayat terlalu pendek atau terlalu panjang, pendua dan sitasi sekunder. Tetapan setiap kerja: **Bahasa hasil** (Bahasa Melayu atau Bahasa Inggeris), **Jenis sintesis** (14 pilihan: biar pembantu cadangkan, kesepakatan, percanggahan, saling melengkapi, tematik, kronologi, takrif, teori dengan bukti, mekanisme, metodologi, konteks, jurang, pendirian penulis, dapatan sendiri dengan kajian lepas; setiap jenis memaparkan resipi ayatnya), **Tahap bantuan**, **Sasaran tulisan** (mana-mana seksyen Tulisan Tesis atau Artikel Penerbitan) dan **Susunan sitasi** berkumpulan (garis panduan tesis UPSI 16.10.2: tahun terkini dahulu; atau APA 7: abjad; automatik mengikut sasaran dan bahasa), serta **Konteks perbincangan** dan **Ramalan saya** (teka dahulu hubungan antara sumber; pembantu membandingkannya). Kanvas **HASIL** (kanan) memaparkan jawapan pembantu dalam satu panggilan API berstruktur: (1) **kesesuaian** dahulu (sesuai, sebahagian, atau tidak sesuai; ayat lemah dan ayat yang perlu diganti dinamakan bersama apa yang patut dicari sebagai ganti; jika tidak sesuai, tiada sintesis dipaksa dan sebarang perenggan daripada model dibuang), (2) jenis sintesis yang sepadan, (3) **peta idea** (sumber disusun mengikut idea, bukan pengarang), (4) **hubungan antara sumber**, (5) **contoh sintesis** dengan fungsi setiap ayat (tuntutan, bukti bersama, perbandingan, syarat, tafsiran penulis, jurang, kaitan), penanda wacana diserlahkan dan klik pada ayat menyerlahkan ayat bahan yang menyokongnya, (6) cara sintesis itu dibina, (7) **di mana sesuai ditulis** (seksyen tesis atau artikel Prof Dr sendiri, dengan butang Jadikan sasaran dan Buka), (8) penanda wacana yang digunakan, dan (9) soalan pembantu. Pembantu hanya menggunakan ayat dalam BAHAN: label sumber yang tidak wujud dibuang, dan **sitasi di luar bahan ditanda merah**. **Tangga bantuan** tiga tahap mengurangkan bantuan: Tahap 1 contoh penuh, Tahap 2 rangka ayat berlompang dengan pilihan penanda, Tahap 3 Prof Dr menulis dahulu dan pembantu hanya menyemak; tahap dicadangkan daripada rekod semakan (tiga tulisan lulus untuk naik tahap; ketetapan aplikasi). Ruang **Tulisan saya** ialah parafrasa atau sintesis Prof Dr sendiri: pengesan gaya tanpa token menilai laporan lawan sintesis (ayat bermula dengan nama pengarang, ayat yang memikul dua sumber, penanda hubungan, ayat tafsiran, sumber berblok), menyemak bentuk Bahasa Melayu terhadap senarai Bentuk dielakkan, susunan sitasi berkumpulan, sitasi di luar bahan, dan rangkaian perkataan yang terlalu hampir dengan ayat sumber atau dengan contoh; "Semak tulisan saya" meminta pembantu menilai gaya, **kesetiaan kepada setiap sumber** (tepat, longgar, tersasar, tidak digunakan), langkah pembaikan dan satu contoh gerakan, tanpa menulis semula perenggan. "Hantar ke RAM" memasukkan Tulisan saya (atau contoh, berlabel belum diparafrasa) ke RAM seksyen sasaran. **Pustaka** di bawah kanvas memuatkan penanda wacana dan rangka ayat mengikut 13 fungsi dalam Bahasa Melayu dan Bahasa Inggeris (ditulis sendiri untuk aplikasi ini), kata kerja pelaporan mengikut sikap, glosari, **Bentuk dielakkan** yang bersandar pada jawapan Khidmat Nasihat Bahasa DBP bertarikh (contohnya "oleh sebab" bukan "oleh kerana", "manakala" tidak memulakan ayat, "justeru" bukan ganti "oleh itu"), frasa sendiri dan tanda bintang; klik frasa memasukkannya ke Tulisan saya. **Kemajuan saya** merekod contoh, rangka, semakan, ketepatan ramalan dan fungsi wacana yang pernah digunakan; **Asas dan sumber kaedah ini** menyenaraikan 15 peraturan menu berserta jenis bukti dan 21 rujukan (DOI dipadankan dengan Crossref; label menunjukkan teks penuh atau abstrak sahaja yang dibaca). Simpanan: `meta/bengkel_indeks`, `meta/bengkel_<id>`, `meta/bengkel_pustaka`, `meta/bengkel_kemajuan` dan salinan tempatan; padam kerja hanya menyembunyikannya daripada senarai. Menu ini berbeza daripada Rantaian sintesis medan 12 (`mod/sintesis.js`), yang menjejak hubungan antara rekod artikel.
- **Sintesis, v1.27.0** (sitasi berbilang, tulis ganti sitasi, tetingkap Cadangan Sintesis searas dengan Tulisan saya): (1) **Satu ayat, beberapa sitasi**: butang "+ Sitasi" pada setiap kad BAHAN menambah sitasi kedua hingga keenam (pengarang, tahun, muka surat) bagi ayat yang sama; "+ Dipetik dalam" menandakan **sitasi sekunder**, iaitu artikel yang benar-benar dibaca. Pembantu menerima kesemuanya pada baris sumber ayat itu (`Sumber: A (2022); B (2020) | DIBACA DALAM: C (2020)`) dan menulis sitasi sekunder mengikut APA 7, Seksyen 8.6 ("seperti yang dipetik dalam" atau "as cited in"; padanan Melayu ialah ketetapan aplikasi kerana garis panduan tesis UPSI tidak memuatkan peraturan khusus). "Tampal banyak ayat" mengesan beberapa sitasi dalam satu kurungan dan frasa sitasi sekunder. (2) **Tulis ganti sitasi**: tanpa token, aplikasi membandingkan sumber pada kad dengan sitasi yang tertulis di dalam teks ayat dan menandakan sitasi sekunder, sitasi yang tidak sepadan (nama atau tahun hampir sama), ayat yang memikul sitasi tambahan, dan kad tanpa sumber; tahun pada kad turut disemak silang dengan rekod repositori. Setiap tanda membawa butang satu klik ("Tulis ganti: ... dipetik dalam ...", "Guna sumber asal sahaja", "Tambah ke kad", "Kekalkan") pada kad dan dalam ruang Analisis, "Betulkan semua sitasi" bagi beberapa kad sekali gus, dan Batal pada toast. Pembantu juga boleh menandakan sitasi sekunder atau salah bagi setiap ayat (medan `sitasi` dalam `kesesuaian.ayat`), tetapi cadangannya hanya diterima jika nama dan tahun itu benar-benar tertulis dalam teks ayat, supaya tiada sitasi direka. Cadangan yang ditulis sebelum bahan atau sitasinya berubah ditanda lapuk dengan butang "Minta semula". (3) **Susun atur**: paparan memenuhi lebar tetingkap (margin kiri dan kanan 8 px, senarai kerja 200 px dan boleh disembunyikan). Baris atas memuatkan **BAHAN** dan **ANALISIS** (kelas setiap ayat, semakan sitasi, jenis, peta idea, hubungan, cara dibina, tempat menulis); baris bawah memuatkan dua tetingkap pada aras yang sama dan sama tinggi: **CADANGAN SINTESIS** (kiri, ditulis oleh pembantu) dan **TULISAN SAYA** (kanan). "Salin ke Tulisan saya" memindahkan cadangan untuk disunting (tulisan asal boleh dipulihkan), meter "% sama dengan cadangan" menunjukkan sejauh mana ia sudah disunting, dan "Fokus sunting" menyembunyikan bahagian lain supaya dua tetingkap itu memenuhi skrin. Klik satu ayat cadangan memaparkan ayat bahan yang menyokongnya di bawah cadangan. (4) **Warna**: lima golongan ditanda dengan warna berlainan dalam cadangan dan, sebagai lapisan di belakang kotak taip, dalam Tulisan saya: penanda wacana, kata kerja pelaporan, istilah sintesis, sitasi dan suara penulis (leksikon tetap dalam `mod/bengkel-data.js`, ditambah penanda yang dinamakan pembantu). Legenda memaparkan kiraan dan boleh menghidupkan atau mematikan setiap warna; jadual kecil membandingkan kiraan Cadangan dengan Tulisan saya. (5) **Jawapan terpotong**: had token keluar dinaikkan (contoh 8,000, rangka 6,500, semakan 6,000; had lama 3,200 memotong jawapan Bahasa Melayu sebelum contoh sempat ditulis), arahan memuatkan had panjang bagi setiap huraian, permintaan diulang sekali dengan had 16,000 jika masih terpotong, bahagian yang sempat ditulis dipaparkan dengan amaran, dan token setiap panggilan direkod walaupun jawapan gagal dibaca. Asas kaedah kini 16 peraturan dan 22 rujukan (tambahan: American Psychological Association, 2022, Secondary sources, https://apastyle.apa.org/style-grammar-guidelines/citations/secondary-sources).
- **Jenis sumber** (borang rekod, Medan 1; v1.27.0): pilihan **Prosiding** ditambah sebelum Lain-lain, pada borang, pada tapisan Papan dan pada pilihan yang diterima oleh "Mohon Prof Dr Claude isikan" (kertas prosiding dikelaskan Prosiding; reka bentuknya kekal pada medan Reka bentuk). - **Sintesis, v1.28.0** (Arah hujah saya dan soal jawab tanpa soalan berulang): (1) **Arah hujah saya (pilihan)** di bawah Konteks perbincangan: sembilan medan yang dibuka dengan mengklik cipnya, iaitu Jurang yang mesti ditonjolkan, Pertentangan antara sumber, Mengapa penting dan kepada siapa, Setuju dengan tambahan, Setuju dengan syarat, Setengah setuju (ya, tetapi), Setengah tidak setuju (tidak, tetapi), Tidak setuju kerana, dan Bantahan yang dijangka. Setiap medan menerima sehingga 500 aksara, tiada satu pun wajib, dan isinya disimpan bersama kerja (`arah`). Gerakan itu dipilih daripada Graff, Birkenstein dan Durst (2018), *"They say / I say"* edisi keempat, Bab 1, 4, 6, 7 dan 15; nama medan, soalan pandu dan contoh isian ditulis sendiri dalam Bahasa Melayu dan templat buku tidak disalin. (2) **Kenyataan Prof Dr tidak ditanya semula**: arahan pembantu kini menganggap Konteks perbincangan, Arah hujah dan jawapan Prof Dr sebagai pendirian penulis yang digunakan terus, ditulis sebagai suara penulis tanpa sitasi dan tidak boleh diletakkan di bawah nama sumber; dakwaan tentang sumber tetap hanya daripada ayat BAHAN. (3) **Soalan pembantu boleh dijawab di tempatnya**: setiap soalan mempunyai ruang jawapan pilihan dan butang "Minta semula dengan jawapan ini"; soalan dan jawapan disimpan pada kerja (`soal`, sehingga 12), dihantar semula sebagai SOAL JAWAB TERDAHULU, dan soalan yang diulang dengan ayat lain ditapis sebelum dipaparkan (paling banyak dua soalan baharu bagi satu permintaan). Kerja lama memindahkan soalan sesi lampau ke ingatan itu secara automatik. (4) **Ayat arah hujah ditonjolkan**: pembantu menandakan ayat yang menzahirkan setiap medan (`gerak`); ayat itu berlabel dan bergaris bawah dalam Cadangan Sintesis, disenaraikan di bawah cadangan ("Jurang: ayat 3" atau "belum muncul") dan pada kad medannya. Label itu hiasan CSS, maka tidak ikut tersalin. (5) **Bersandar pada kenyataan Prof Dr**: butiran tentang sumber yang datang daripada kenyataan Prof Dr dan tiada dalam BAHAN disenaraikan berasingan supaya disahkan dengan artikel asal. (6) Cadangan ditanda basi apabila konteks, arah hujah atau jawapan berubah; mod semak melaporkan sama ada setiap medan sudah ditulis dalam Tulisan saya; pengesan tanpa token memberi petunjuk jika medan Jurang, Pertentangan atau Setuju dengan syarat diisi tetapi penandanya belum ada dalam tulisan. Asas kaedah kini memuatkan 17 peraturan dan 23 rujukan.
- **Semakan pendua**: sebelum pemilihan, aplikasi mengecualikan semua DOI yang pernah dicadangkan (log awan `meta/cadangan_log`, log tempatan peranti, sejarah cadangan awan dan tempatan), DOI dan tajuk rekod repositori, ID OpenAlex, serta 497 DOI daripada log tugas harian lama (`data/seen_dois.json`). Baris "Semakan pendua" di bawah kad memaparkan bilangan yang dikecualikan dan status log awan; jika log awan tidak dapat dibaca atau ditulis (peraturan Firestore belum diterbitkan), semakan hanya tepat pada peranti itu dan amaran dipaparkan. Muat naik PDF yang DOI-nya sudah ada dalam repositori dipautkan ke rekod sedia ada atau dilangkau.
- **Rantaian artikel** (konsep *connected papers*): bagi setiap konstruk, calon hari ini diambil daripada senarai Rujukan artikel yang dicadangkan sebelumnya, dengan tapisan yang sama (Scopus dahulu, julat tahun, akses terbuka, relevansi istilah konstruk). Rantaian diteruskan selagi senarai Rujukan masih mengandungi penerbitan dalam julat tahun itu; jika tiada, carian baharu dimulakan dan sebabnya dinyatakan pada kad. Setiap kad menunjukkan "Rantaian ke-n" bersama artikel asalnya, dan bahagian "Rantaian artikel" di bawah kad memaparkan keseluruhan rantaian setiap konstruk mengikut tarikh.
- **Web Artikel** (rajah jaringan bibliometrik tempatan): klik mana-mana rujukan dalam bahagian Rantaian artikel untuk membuka tetingkap jaringan dengan artikel itu di tengah. Nod ialah artikel dalam repositori dan cadangan harian sahaja (tiada carian baharu), dalam julat tahun yang sama. Kekuatan hubungan dikira daripada rantaian atau petikan terus (senarai rujukan OpenAlex), gandingan bibliografi (rujukan sepunya), persamaan teks TF-IDF (tajuk, abstrak, medan ekstrak dan ayat yang diindeks dalam Peta Ayat), penulis pertama, tema dan jurnal; garisan tebal dan pekat bermakna hubungan kuat, nipis dan pudar bermakna lemah, dan nod disusun dalam tiga gelang mengikut kekuatan. Klik dua kali nod atau "Jadikan pusat" untuk menjadikannya pusat; PNG mengeksport rajah.
- **Senarai Scopus**: `data/scopus.json` dibina daripada Scopus Source Title List November 2024 (senarai awam Elsevier, helaian Scopus Active, 28,766 jurnal) dengan `tools/bina_scopus.py`; kuartil ialah anggaran daripada SJR 2023 mengikut kategori ASJC, maka pengesahan rasmi tetap melalui pautan Semak SJR. Untuk mengemas kini, muat turun senarai terbaru dari https://www.elsevier.com/resources/scopus-titlelists dan jalankan skrip itu.
- **Satu sumber untuk semua peranti**: setiap PDF, sama ada dimuat naik di Windows, Android atau pelayar, disimpan dalam folder "Repositori SLR" di Google Drive dan rekodnya dalam Firestore; peranti lain membacanya terus dari situ. "Simpan ke Drive" mencuba tiga laluan mengikut urutan: salinan OpenAlex (`content.openalex.org`, kira-kira 100 fail sehari dengan kunci API percuma), pautan penerbit (jika penerbit membenarkan), dan akhirnya langkah manual (Buka PDF, simpan, kemudian Pilih fail PDF atau seret ke kad). Di Android, fail PDF juga boleh dikongsi terus ke aplikasi (Kongsi > Repositori SLR); fail yang dikongsi dimuat naik ke Drive dan, jika DOI dalam PDF sepadan dengan cadangan hari ini, dipautkan ke kad itu secara automatik.
- **Peta Ayat**: taip istilah; semua ayat yang mengandunginya daripada semua PDF yang diindeks dikumpulkan, dikelompokkan mengikut pola istilah yang sama, dengan sumber (Bil., penulis, tahun, muka surat), butang Buka (flipbook pada muka surat itu), Salin dengan sitasi dan Eksport CSV. "Frasa tepat" mencari urutan perkataan yang sama.
- **Tetapan**: kunci API OpenAlex (percuma, disyorkan), kunci API Anthropic dan model untuk "Mohon Prof Dr Claude isikan", serta profil kajian. Tetapan disimpan dalam Firestore (`meta/tetapan`) dan salinan tempatan peranti; jika Firestore menolak, aplikasi memberitahu bahawa tetapan hanya tersimpan pada peranti itu. Tanpa kunci, bajet awam ialah kira-kira 100 carian atau 10 muat turun sehari yang dikongsi semua pengguna pada alamat IP yang sama; dengan kunci, 1,000 carian atau 100 muat turun sehari.
