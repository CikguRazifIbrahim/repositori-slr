# Repositori SLR

Aplikasi web boleh pasang (PWA) untuk merekod 13 medan ekstrak bagi setiap artikel jurnal, menyimpan PDF dalam Google Drive dan menyegerakkan rekod ke semua peranti (Windows, Android, pelayar).

Rekod disimpan dalam **Firestore** (projek Firebase sendiri, percuma, sokongan luar talian). Fail PDF disimpan dalam folder **"Repositori SLR"** di **Google Drive** akaun sendiri (percuma, 15 GB). Kod aplikasi dihoskan di **GitHub Pages**.

## Persediaan sekali sahaja

Semua langkah di bawah dibuat dalam pelayar pada komputer. Anggaran masa: 20 minit.

### A. Firebase (Firestore dan log masuk)

1. Buka https://console.firebase.google.com dan pilih projek sedia ada (contoh: projek MyKajian) atau cipta projek baharu.
2. **Authentication > Sign-in method**: pastikan **Email/Password** diaktifkan. Pada tab **Users**, pastikan akaun e-mel pemilik wujud (tambah jika belum).
3. **Authentication > Settings > Authorized domains**: tambah domain GitHub Pages, contohnya `cikgurazifibrahim.github.io`.
4. **Firestore Database**: jika belum ada, klik **Create database** (mod *production*, lokasi `asia-southeast1`).
5. **Firestore Database > Rules**: gantikan peraturan dengan blok berikut (atau tambah koleksi `teks` dan `cadangan` jika blok `artikel` dan `meta` sudah ada), kemudian **Publish**. Gantikan e-mel dengan e-mel pemilik.

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       function pemilik() { return request.auth != null && request.auth.token.email == "saya@cikgurazif.com"; }
       match /artikel/{id} { allow read, write: if pemilik(); }
       match /meta/{id} { allow read, write: if pemilik(); }
       match /teks/{id} { allow read, write: if pemilik(); }
       match /cadangan/{id} { allow read, write: if pemilik(); }
       match /users/{uid}/{document=**} { allow read, write: if request.auth != null && request.auth.uid == uid; }
     }
   }
   ```

   Koleksi `teks` menyimpan ayat yang diekstrak daripada PDF (Peta Ayat) dan `cadangan` menyimpan tiga artikel harian. Tanpa dua baris itu, kedua-dua ciri berfungsi pada satu peranti sahaja (disimpan setempat) dan aplikasi memaparkan amaran.

6. **Project settings (ikon gear) > General > Your apps**: pilih aplikasi web (ikon `</>`) atau cipta satu, kemudian salin objek `firebaseConfig` (apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId).

### B. Google Cloud (akses Google Drive)

Projek Firebase ialah projek Google Cloud yang sama. Buka https://console.cloud.google.com dan pilih projek itu di bahagian atas.

1. **APIs & Services > Library**: cari **Google Drive API** dan klik **Enable**.
2. **APIs & Services > OAuth consent screen** (atau **Google Auth Platform > Branding**):
   - App name: `Repositori SLR`; User support email dan Developer contact: e-mel sendiri.
   - **Audience**: External. Selepas disimpan, klik **Publish app** supaya statusnya *In production* (tanpa langkah ini, kebenaran tamat setiap 7 hari).
   - **Data access / Scopes**: tambah skop `https://www.googleapis.com/auth/drive.file` (skop bukan sensitif, tidak memerlukan pengesahan Google).
3. **APIs & Services > Credentials > Create credentials > OAuth client ID**:
   - Application type: **Web application**; Name: `Repositori SLR Web`.
   - **Authorized JavaScript origins**: `https://cikgurazifibrahim.github.io` (tanpa laluan, tanpa garis miring di hujung).
   - **Authorized redirect URIs**: `https://cikgurazifibrahim.github.io/repositori-slr/` (dengan garis miring di hujung). Ini membolehkan "Sambung Drive (cara lencongan)" apabila tetingkap kebenaran Google disekat dalam aplikasi yang dipasang.
   - Klik **Create** dan salin **Client ID** (berakhir dengan `.apps.googleusercontent.com`).

### C. Masukkan nilai ke dalam `config.js`

Buka fail `config.js` dalam repo ini (boleh diedit terus di GitHub: klik fail, ikon pensel, edit, *Commit changes*). Gantikan setiap nilai yang bermula dengan `ISI_`:

- `firebase.*` daripada langkah A6
- `googleClientId` daripada langkah B3
- `ownerEmail` ialah e-mel akaun log masuk (mesti sama dengan e-mel dalam peraturan Firestore)

GitHub Pages menerbitkan semula secara automatik dalam satu hingga dua minit.

### D. Pasang sebagai aplikasi

- **Windows (Chrome atau Edge)**: buka alamat aplikasi, klik ikon *Install* di hujung bar alamat, atau menu tiga titik > *Cast, save and share* > *Install page as app*. Aplikasi muncul di menu Start.
- **Android (Chrome)**: buka alamat aplikasi, menu tiga titik > *Add to Home screen* > *Install*. Aplikasi muncul di skrin utama dan dibuka tanpa bar pelayar.

Kali pertama memuat naik PDF pada setiap peranti, Google akan meminta kebenaran akses Drive sekali.

Token Drive tamat kira-kira sejam selepas disambung. Cip "Drive disambung" bertukar kepada **Sambung Drive** apabila token tamat (disemak setiap 30 saat dan apabila tab kembali aktif). Jika token tamat atau ditolak ketika muat naik sedang berjalan, aplikasi tidak lagi cuba membuka tetingkap kebenaran secara automatik (pelayar menyekat tetingkap yang dibuka tanpa klik pengguna, lalu muat naik gagal dengan "tetingkap kebenaran Google disekat"); sebaliknya fail yang belum selesai disimpan sebagai tertangguh dan butang **Sambung Drive dan teruskan** (pada baris log muat naik, pada pemberitahuan, dan melalui cip Sambung Drive) menyambung semula dalam klik pengguna lalu meneruskan muat naik fail yang sama tanpa perlu dipilih semula. Jika tetingkap kebenaran tidak muncul dalam aplikasi yang dipasang (biasa berlaku pada Windows apabila pop-up disekat), buka menu tiga titik dan pilih **Sambung Drive (cara lencongan)**. Aplikasi beralih ke halaman Google, kemudian kembali dengan token. Menu **Diagnostik Drive** menunjukkan punca sebenar sebarang kegagalan dan nilai yang mesti didaftar dalam Google Cloud.

## Ciri utama

- **Papan**: senarai artikel dengan tapisan, statistik, muat naik PDF (seret dan lepas), butang **Baca** (flipbook terapung) dan **Muat turun** bagi artikel yang belum selesai dibaca (paparan Senarai). Paparan lalai ialah **Kumpulan label** (`mod/kumpulan.js`): artikel dikelompokkan mengikut label, iaitu Tema utama rekod, dengan susunan Kepimpinan Digital, Pengurusan Pengetahuan Organisasi, Kompetensi Digital Guru, kemudian Lain-lain; artikel yang belum dilabel diletakkan paling atas dengan cip label pantas (KD, PPO, KDG, Lain) dan **cadangan automatik** (peraturan istilah pada tajuk, objektif, konstruk dan subtopik serta jiran terdekat TF-IDF dalam kalangan artikel yang sudah dilabel, dengan sebab yang dipaparkan; butang "Terima cadangan yang pasti" melabel semuanya sekali gus selepas pengesahan). Dalam setiap kumpulan, artikel Selesai di atas, kemudian Sedang dibaca dan Belum dibaca, dengan pilihan Susun sebagai urutan kedua; kepala kumpulan menunjukkan bilangan mengikut status, melekat ketika menatal dan boleh dilipat (diingat pada peranti); baris dipaparkan padat (Bil., penulis, status, tajuk satu baris, relevansi, PDF, tarikh) tanpa butang Baca dan Muat turun; tiada ketinggian tetap bagi kumpulan. Pilihan Paparan (Kumpulan label atau Senarai) disimpan pada peranti; tapisan dan carian terpakai kepada kedua-dua paparan. Pilihan **Susun** merangkumi **Tarikh muat naik, terbaharu dahulu** dan **Tarikh muat naik, terlama dahulu** (mengikut masa fail PDF terbaharu rekod itu dimuat naik ke Drive, `fail[].masa`; rekod tanpa PDF mengikut masa rekod dicipta). Dalam paparan Kumpulan label, kumpulan pemboleh ubah kekal dan susunan tarikh berlaku di dalam setiap kumpulan sebagai urutan tarikh tulen (hari ini, semalam, dan seterusnya; status bacaan tidak didahulukan bagi dua susunan ini, berbeza daripada susunan lain yang mendahulukan Selesai). Tapisan **Dimuat naik** menapis mengikut masa yang sama: julat (hari ini, 3, 7, 14, 30 atau 90 hari lepas) atau satu tarikh tertentu daripada **kalendar muat naik** (`mod/kalendar.js`) di bawah pilihan itu: kalendar bulanan kecil menandakan hari yang ada muat naik dengan bilangan artikel, hari ini bergaris, hari akan datang dilumpuhkan, anak panah menukar bulan dan "Hari ini" kembali ke bulan semasa; klik satu hari untuk melihat artikel hari itu sahaja (kumpulan pemboleh ubah dan susunan kekal, pilihan "Pada <tarikh>" muncul dalam senarai juntai), klik hari yang sama atau "Buka semula" untuk membukanya. Apabila susunan atau tapisan muat naik aktif, tarikh pada setiap baris (kedua-dua paparan) menunjukkan "Dimuat naik" atau "Dicipta" dan bukannya masa kemas kini, dan nota di bawah kepala senarai menerangkan urutan atau tarikh yang sedang dipakai. Eksport CSV mempunyai lajur Dimuat naik. Semua senarai juntai artikel (Artikel 1 dan Artikel 2 dalam Banding, artikel sumber dan pasangan soal jawab dalam Artikel, Tambah hubungan dalam medan 12) menggunakan pembina yang sama (`Kumpulan.pilihanHtml`): dikelompokkan mengikut pemboleh ubah (KD, PPO, KDG, Lain, kemudian Belum dilabel) dengan bilangan mengikut status pada kepala kumpulan, Selesai dahulu dalam setiap kumpulan, dan setiap baris membawa tanda status, Bil., penulis, tahun, kelengkapan A hingga F dan tajuk.
- **Rekod**: 13 medan ekstrak, pemapar PDF skrin penuh atau bersebelahan borang, flipbook, muat turun, dan **Indeks ayat** untuk Peta Ayat. Kotak teks Kekuatan dan Kelemahan (medan 10) selebar borang dan disusun menegak, sama seperti kotak Jurang, supaya ayat tidak terpenggal; setiap kotak teks boleh dibesarkan dengan menyeret penjuru kanan bawah. **Rantaian sintesis** (medan 12 Bandingan silang, `mod/sintesis.js`): di bawah teks bebas medan 12, setiap rekod menyimpan senarai `hubungan` berstruktur dengan artikel lain dalam repositori (jenis: selari, bercanggah, melanjutkan, melengkapi, mengulang, berbeza konteks; aspek: teori, konstruk, kaedah, instrumen, sampel dan konteks, dapatan, jurang, implikasi; nota satu atau dua ayat). Hubungan ditulis sekali dan dipaparkan dua hala ("Dirujuk oleh" dalam rekod artikel itu, dengan butang Balas hubungan); setiap baris mempunyai **Ringkasan kilat** (objektif, konstruk, teori, kaedah, instrumen, dapatan, jurang, relevansi artikel itu) supaya artikel yang sudah lama dibaca diingat semula tanpa membukanya, serta butang Buka rekod dan Banding. **Mungkin berkaitan** mencadangkan artikel lain secara automatik daripada medan (tema sama, teori sepunya yang dikesan daripada medan teori, definisi, konstruk dan instrumen, reka bentuk, kesan pengantaraan, peringkat, negara, asas teori, subtopik, dan istilah sepunya TF-IDF) dengan sebab yang telus dan skor. **Rangka sintesis** menyusun semua hubungan rekod itu (termasuk yang masuk) menjadi perenggan rangka deterministik tanpa token, yang boleh dimasukkan ke hujung medan 12; **Peta sintesis** memaparkan kelompok artikel yang saling berkait dalam seluruh repositori (tapis aspek dan jenis, Rangka kelompok, eksport CSV). Eksport CSV utama mempunyai lajur Hubungan sintesis.
- **Mohon Prof Dr Claude isikan**: butang pada setiap bahagian A hingga F (dan "Isi semua bahagian" di kepala rekod). Aplikasi mengekstrak teks penuh PDF artikel (penanda muka surat [m.s. N]; PDF imbasan tanpa teks dihantar sebagai dokumen, maksimum 100 muka surat), menghantarnya terus dari pelayar ke API Anthropic (Messages API, `https://api.anthropic.com/v1/messages`, pengepala `anthropic-dangerous-direct-browser-access`) dengan kunci API Prof Dr yang disimpan dalam Tetapan, dan mengisi hanya medan yang masih kosong sebagai draf; nilai yang sudah ditulis tidak disentuh. Arahan kepada model: Bahasa Melayu Malaysia akademik, sifar fabrikasi ("Tiada dalam artikel" jika tidak dilaporkan), jejak muka surat bagi angka dan definisi, salin tepat hanya rujukan, statistik dan petikan definisi, pilihan senarai mesti tepat. Jawapan diterima melalui output berstruktur `output_config.format` (`json_schema`): API menjamin jawapan ialah JSON yang sah mengikut satu skema semua medan (skema yang sama bagi setiap bahagian supaya cache prompt kekal sah; 19 medan pendek diwajibkan dengan nilai "-" jika bukan bahagian yang diminta, 22 medan panjang pilihan, mematuhi had API 24 medan pilihan), maka nilai tidak lagi rosak pada tanda petik atau baris baharu seperti teks bebas. `tool_choice` jenis `tool` atau `any` tidak digunakan kerana model keluarga 5.5 menolaknya dengan ralat 400. Jika API menolak skema (ralat 400, tidak dicaj), aplikasi beralih secara automatik kepada alat `isi_medan` dengan `tool_choice` `auto`, kemudian kepada teks JSON biasa, dan mengingati mod yang berjaya bagi model itu. Sejak v1.31.0 arahan bahasa datang daripada piawaian bahasa bersama, dan medan teks yang diisi dipiawaikan oleh Agen Bahasa (butiran seterusnya). Had token keluaran sejak v1.31.1 ialah 18,192, iaitu bajet jawapan 8,192 ditambah 10,000 token ruang berfikir model (butiran dalam butir Had token keluaran di bawah); jika jawapan terpotong (`stop_reason: max_tokens`), aplikasi mengulang sekali secara automatik pada siling 21,000 dengan arahan meringkaskan dan effort yang sama (awalan sudah dalam cache, maka ulangan murah), dan jika jawapan pertama kosong kerana had habis semasa model berfikir, ulangan dihantar dengan effort rendah tanpa arahan meringkaskan; kegagalan selepas ulangan dilaporkan bersama token yang digunakan. Jika jawapan tiba sebagai teks yang rosak, pembaikan JSON sandaran (pagar kod, tanda petik tidak dilepaskan, baris baharu mentah, koma hujung, kurungan terpotong) dicuba sebelum ralat dilaporkan. Bahagian E dan F merujuk profil kajian Prof Dr (boleh disunting dalam Tetapan) dan bahagian F turut menerima ringkasan artikel lain dalam repositori untuk bandingan silang. Teks artikel dan arahan sistem ditanda `cache_control` supaya bahagian berikutnya artikel yang sama lebih murah. Setiap bahagian yang diisi ditanda "Draf AI" dengan masa, model dan bilangan medan (disimpan dalam medan `aiIsi` rekod). Model: Claude Sonnet 5.5 (lalai), Haiku 5.5 atau Opus 5.5.
- **Agen Bahasa dan piawaian bahasa** (v1.31.0; `mod/bahasa.js` dan `mod/bahasa-data.js`): setiap teks yang dijana mesti berbahasa Melayu Malaysia akademik dan selaras dengan senarai istilah Prof Dr. (1) **Punca**: Temperature, Top-K dan Top-P bukan puncanya dan tidak boleh dilaras. Dokumentasi API Anthropic meminta ketiga-tiganya ditinggalkan bagi model keluarga 5.5; Sonnet 5.5 dan Opus 5.5 menolak permintaan yang menetapkannya dengan ralat 400, maka aplikasi tidak pernah menghantarnya. Bentuk Indonesia dan istilah yang tidak selaras berpunca daripada arahan bahasa yang terlalu umum, dan beberapa istilah dalam arahan lama sendiri tidak mengikut senarai istilah Prof Dr (kadar respons, alfa Cronbach, perantaraan). (2) **Piawaian bahasa bersama**: satu blok arahan (`PIAWAI_PENUH` bagi agen isian dan Agen Bahasa; `PIAWAI_RINGKAS` bagi Banding, soal jawab Artikel, Pandu Tulis, Sintesis dan Pembantu Tajuk) yang memuatkan senarai istilah Prof Dr (138 pasangan Inggeris dan Bahasa Melayu dalam sepuluh kumpulan, termasuk istilah teori kepimpinan mengikut proposal beliau), bentuk Indonesia dengan gantinya, kesan terjemahan yang perlu dibuang dan perkataan yang dilarang. (3) **Pengesan istilah tanpa token**: setiap bahagian rekod disemak pada peranti terhadap 126 corak; cip "N istilah untuk disemak" pada kepala bahagian membuka senarai kejadian dengan gantinya dan dikemas kini semasa teks dibetulkan. Teks dalam tanda petik dan nama khas tidak disemak. Menu tiga titik, **Semakan bahasa semua rekod (tanpa token)**, menyenaraikan rekod yang masih memuatkan istilah untuk dipiawaikan, paling banyak dahulu, dengan butang Buka rekod. (4) **Agen Bahasa**: selepas "Mohon Prof Dr Claude isikan", isian disimpan dahulu, kemudian satu panggilan kecil (teks medan sahaja, bukan PDF) memiawaikan medan teks yang baru diisi ("Isi semua bahagian" memanggil agen sekali sahaja di hujung, bukan enam kali); butang **Piawaikan bahasa** pada setiap bahagian dan **Piawaikan bahasa (A hingga F)** di kepala rekod melakukan perkara yang sama bagi teks yang sudah ada, dengan pratonton sebelum dan selepas serta kotak tanda bagi setiap medan. Agen hanya meminda bahasa: pengawal isi menolak teks baharu yang angka, simbol statistik, petikan atau jejak muka suratnya berubah, atau yang panjangnya berubah terlalu banyak; jawapan yang terpotong pada had token tidak dibaiki tetapi diulang sekali, dan JSON yang rosak ditolak tanpa pembaikan; medan yang sempat disunting oleh Prof Dr semasa agen bekerja tidak ditimpa; kegagalan agen tidak menjejaskan isian yang sudah disimpan. Medan yang disalin tepat daripada artikel atau milik Prof Dr sendiri (tajuk, rujukan, DOI, penulis, tahun, negara, subtopik, jejak, catatan) tidak dihantar. Setiap pindaan dicatat pada rekod (`bahasaIsi`) dan boleh dilihat melalui cip "Bahasa dipiawaikan". (5) **Tetapan**: Agen Bahasa selepas isian boleh ditetapkan kepada sentiasa (lalai), hanya apabila pengesan menemui istilah, atau tidak. (6) Teks panduan, label Ruang Output dan templat Bab 4 diselaraskan dengan senarai istilah yang sama (kadar pulangan, kesahan menumpu dan mencapah, indeks kesepadanan model, Cronbach Alpha, pengantaraan); pilihan tersimpan "Perantaraan" pada medan Kesan yang diuji tidak diubah.
- **Had token keluaran dan pemikiran model** (v1.31.1; `mod/isi.js`, penghantar bersama semua agen): (1) **Punca "Agen gagal: jawapan kosong diterima"**: model keluarga 5.5 berfikir dahulu sebelum menjawab (adaptive thinking; sentiasa hidup bagi Opus 5.5). Token pemikiran dicaj sebagai token keluar dan dikira dalam `max_tokens`, yang merupakan had ketat. Had lama ialah angka tetap yang kecil (cadangan penulisan Pandu Tulis 6,000, perbincangan 3,600, soalan bebas 3,000), maka pemikiran boleh menghabiskan seluruh had sebelum teks jawapan sempat ditulis: jawapan tiba dengan `stop_reason: max_tokens` tanpa blok teks, tetap dicaj, dan tidak dikira dalam jumlah token pada skrin. Dokumentasi API menyarankan dua langkah: beri ruang dalam `max_tokens` bagi pemikiran dan jawapan, atau rendahkan `effort`. (2) **Had = bajet jawapan + ruang berfikir**: setiap pemanggil menyatakan bajet jawapan, dan penghantar menambah 10,000 token ruang berfikir dengan siling 21,000 (di bawah 21,333, ambang yang memerlukan penstriman). Bajet jawapan mengikut panjang yang diminta: cadangan penulisan Pandu Tulis dikira daripada sasaran patah perkataan folder (had atas sasaran darab tiga token sepatah perkataan, tambah 1,200 bagi senarai sumber dan keputusan; antara 3,000 dengan 11,000), semakan folder daripada panjang teks ASAL yang disemak, semakan menyeluruh daripada panjang ASAL semua folder, bedah artikel contoh daripada panjang artikel itu, dan Agen Bahasa daripada panjang teks medan; perbincangan (3,600), soalan bebas (3,000), soal jawab Artikel (4,000), Pembantu Tajuk, Banding, menu Sintesis dan isian PDF (8,192) mempunyai bentuk jawapan yang tetap. Dialog kos Pandu Tulis dan soal jawab Artikel memaparkan jumlah had, bajet jawapan berserta asasnya, dan ruang berfikir. Had ialah siling, bukan belian: bil dikira atas token yang benar-benar dijana, dan dokumentasi had kadar menyatakan `max_tokens` tidak dikira dalam had kadar token keluaran, maka baki had yang tidak digunakan tidak dicaj dan tidak merugikan. (3) **Ulangan automatik**: jika jawapan kosong, baru bermula (teks kurang daripada suku bajet jawapan) atau output berstruktur terpotong pada `max_tokens`, permintaan diulang SEKALI pada siling 21,000 dengan `output_config.effort` rendah supaya model kurang berfikir dan jawapan sempat ditulis; jika ulangan tidak lebih panjang, teks percubaan pertama digunakan. Teks biasa yang sudah panjang tetapi terpotong tidak diulang (mengulang jawapan yang hampir siap hanya menggandakan kos) dan dipaparkan dengan amaran. Pertukaran effort boleh membatalkan cache prompt, maka token masuk ulangan mungkin dicaj pada kadar penuh; kebolehpercayaan diutamakan kerana ulangan yang gagal membazirkan lebih banyak. (4) **Kiraan token yang jujur**: token semua percubaan dijumlahkan; panggilan yang gagal selepas token dijana dicatat pada artikel (Pandu Tulis: "agen: N panggilan (M gagal)"; soal jawab Artikel: "termasuk N panggilan gagal"; Pembantu Tajuk; menu Sintesis) dan mesej ralat menyatakan token masuk dan keluar yang digunakan. Mesej "jawapan kosong diterima; cuba sekali lagi" diganti dengan mesej yang menyatakan punca dan langkah seterusnya. Soalan yang ditaip dalam soal jawab Artikel kekal dalam kotak jika panggilan gagal. (5) **Tetapan Kedalaman berfikir model (effort)**: Lalai model (tiada apa-apa dihantar; Sonnet 5.5 tinggi, Opus 5.5 dan Haiku 5.5 sederhana), Rendah, Sederhana atau Tinggi, dihantar sebagai `output_config.effort` oleh semua agen. Tahap yang lebih rendah mengurangkan token pemikiran dan kos tetapi boleh mengurangkan ketelitian. Jika API menolak effort (ralat 400, tidak dicaj), permintaan dihantar semula tanpanya dan tetapan itu diabaikan sehingga aplikasi dimuat semula. (6) **Masa menunggu** mengikut had token, antara 4 dengan 10 minit bagi satu permintaan. Batasan: logik ini diuji dengan API tiruan (jawapan kosong, terpotong, ralat 400), bukan dengan kunci sebenar; banyaknya pemikiran model bagi sesuatu tugasan tidak dapat diramal daripada panjang artikel, maka ruang berfikir ditetapkan sebagai angka tetap yang dilindungi oleh ulangan automatik. - **Tulisan Tesis** (tab Tulisan): buku nota penulisan Bab 1 hingga Bab 5 di dalam sistem supaya tiada perenggan yang hilang atau ditaip dua kali. Setiap bab mengandungi seksyen (tajuk dan kandungan). Setiap seksyen mempunyai **dua pane bersebelahan**: **ASAL** di kiri ialah teks akhir seksyen (yang masuk ke Word, kiraan patah, carian dan Semalam), **RAM** di kanan ialah kanvas sementara bahan mentah bagi seksyen yang sama (medan `ram`, disimpan dan disegerakkan seperti ASAL tetapi tidak dieksport ke Word; ditanda "RAM" dalam senarai seksyen dan turut dicari). Paparan Tulisan menggunakan lebar penuh dengan jidar 8 px dan senarai seksyen 250 px; pane disusun menegak pada skrin sempit. **Editor teks kaya** seperti Word: tebal, condong, garis bawah, superskrip dan subskrip, **warna teks** untuk melabel kepentingan (palet enam warna sederhana: merah, biru, hijau, oren, ungu, kelabu, serta Asal untuk membuang warna; pilih teks kemudian klik warna; disimpan sebagai kelas `w-<nama>` dengan tona terang dan gelap mengikut tema, dieksport sebagai warna run dalam Word, dan dibaca semula daripada fail Word dengan membaca `word/document.xml` (JSZip) lalu menjajarkan run berwarna dengan teks HTML mammoth aksara demi aksara; warna Word dipadankan ke warna palet terdekat, hitam dan kelabu gelap dianggap tanpa warna), senarai berbutir dan bernombor, jadual (sisip dengan bilangan baris dan lajur, tambah atau padam baris dan lajur, baris kepala, Tab berpindah sel) dan rajah (fail imej dikecilkan kepada sisi terpanjang 1,600 px dan 600 KB, disimpan dalam dokumen Firestore sendiri `meta/tulisan_imej_<id>` dan dirujuk melalui `data-imej` supaya dokumen bab kekal di bawah had 1 MiB); teks yang ditampal daripada Word mengekalkan format (HTML disaring kepada tag yang dibenarkan sahaja; gaya, kelas dan skrip dibuang; imej daripada papan keratan Word tidak dapat dibaca dan perlu disisip melalui butang Rajah); muat naik Word peringkat seksyen (jadual dan rajah termasuk, tajuk di dalam fail menjadi perenggan tebal) masuk ke RAM seperti di atas; "Salin" menyalin seksyen dengan format ke papan keratan. Setiap artikel penerbitan mempunyai **jenis artikel** (senarai jenis artikel akademik: empirikal, ulasan dan sintesis, konseptual dan teori, metodologi, lain-lain), **artikel sumber** daripada repositori (tiada had bilangan sejak v1.31.0, dengan peringatan token yang dipertegas apabila sumber melebihi 15; dipilih daripada senarai yang dikumpulkan mengikut status bacaan; setiap satu dengan meter kelengkapan Bahagian A hingga F, peratus medan diisi, butang Buka rekod dan Baca), dan **soal jawab merentas semua artikel sumber**: taip soalan (atau klik soalan pantas) dan agen menjawab berdasarkan medan A hingga F semua artikel sumber artikel itu (blok sumber diletakkan dalam arahan sistem supaya dicache oleh API bagi soalan berturut-turut), ringkasan laporan Agen Banding sedia ada antara sumber (disenaraikan dengan butang ke Banding; sehingga lima dirujuk) dan empat soal jawab terdahulu; agen diarahkan mensintesis merentas semua sumber, menamakan artikel yang menyokong setiap dakwaan, dan mengakhiri dengan perenggan "Untuk artikel Prof Dr". Maksimum 10 soalan bagi setiap artikel; **amaran kos** dipaparkan sebelum setiap soalan dihantar (bilangan sumber, anggaran token masuk, model, baki soalan), setiap satu satu panggilan API dengan kunci API Prof Dr; jawapan disusun mengikut soalan dengan skop dan token setiap satu, dan boleh dipindahkan ke RAM seksyen semasa. Badan artikel ialah seksyen sahaja (tiada Bab 1 hingga Bab 5; butang Seksyen baharu dan Struktur lazim mengikut jenis) dengan editor ASAL dan RAM, warna, jadual, rajah, Word masuk dan keluar, sejarah versi, carian dan panel Semalam yang sama seperti Tulisan Tesis (kilang `initTulisan` yang sama dengan konfigurasi artikel). Simpanan: `meta/penerbitan_indeks` dan `meta/penerbitan_<id>` berserta salinan tempatan.
- **Pandu Tulis** (dalam tab Artikel, di bawah soal jawab): bimbingan menulis artikel langkah demi langkah mengikut **acuan artikel contoh**. Bagi setiap keluarga jenis artikel, satu artikel sebenar yang sudah diterbitkan dalam jurnal berwasit telah dibedah bahagian demi bahagian dan perenggan demi perenggan (fungsi setiap perenggan, cara ia dibina, panjang, bilangan sitasi, nisbah setiap bahagian); angka diukur oleh skrip daripada teks penuh, huraian ditulis dengan kata-kata sendiri dan tiada ayat artikel disalin. Artikel contoh terbina: empirikal kuantitatif, Nadav et al. (2026), https://doi.org/10.1111/ejed.70373; kaedah campuran, Bice dan Tang (2022), https://doi.org/10.1007/s10639-022-11044-1; kualitatif, McLeod dan Dulsky (2021), https://doi.org/10.3389/feduc.2021.637075; pembangunan instrumen, Tzafilkou et al. (2022), https://doi.org/10.1186/s41239-022-00330-0; ulasan skop, Karsikas et al. (2022), https://doi.org/10.1111/jonm.13626; ulasan sistematik, Tummers dan Bakker (2021), https://doi.org/10.3389/fpsyg.2021.722080; meta-analisis, Zeng et al. (2022), https://doi.org/10.3389/fpsyg.2022.1091017; bibliometrik, Rojas-Sánchez et al. (2023), https://doi.org/10.1007/s10639-022-11167-5; ulasan naratif, Timotheou et al. (2023), https://doi.org/10.1007/s10639-022-11431-8; kertas konsep, Ng et al. (2023), https://doi.org/10.1007/s11423-023-10203-6. Apabila acuan aktif: **folder** dan subseksyen mengikut bahagian artikel contoh (Abstrak ditulis paling akhir, Rujukan dijana daripada sitasi), sasaran panjang setiap folder mengikut nisbahnya, kad **Lihat acuan** memaparkan rujukan, sebab dipilih, ukuran dan nasihat penyesuaian, dan bahagian **A** dalam setiap folder memaparkan perbandingan draf dengan artikel contoh, peta perenggan dan **pola ayat** Bahasa Melayu generik. Pemilik boleh **membedah artikel contoh sendiri** daripada repositori (satu panggilan agen membaca teks penuh PDF; disimpan dalam `meta/pandu_acuan_<keluarga>`), atau mematikan acuan. **Jurnal sasaran** lalai ialah berindeks MyCite (boleh ditukar kepada Scopus atau WoS; mempengaruhi piawaian semakan agen dan julat sasaran panjang). Setiap folder melalui empat langkah (sejak v1.41.0): (1) artikel panduan, iaitu satu senarai bagi artikel repositori dan rekod CSV, (2) cadangan penulisan daripada agen (kerangka perenggan dan draf dalam satu tekan; soal jawab 5W1H dan soalan terbuka sebagai alat sokongan), (3) penulisan ASAL oleh pemilik, (4) meter dan semakan agen sebelum ditandakan siap. Semua keluaran agen masuk ke **RAM**; **ASAL** tidak pernah ditulis oleh agen. **Meter** (Panjang, Pemboleh ubah, Sitasi, Padanan acuan, Gerakan retorik, Parafrasa, Gaya) dikira semasa menaip dan dipaparkan di atas editor; amaran muncul sebelum folder ditandakan siap. **Ruang PRISMA 2020** (folder Metodologi dan Dapatan artikel ulasan): pangkalan data, tarikh, rentetan carian penuh dan angka aliran diisi oleh pemilik; sistem mengira kotak yang boleh dikira, menyemak aritmetik, melukis rajah templat rasmi dua lajur (BM atau Inggeris), dan menyisip rajah, jadual strategi carian serta ayat aliran berangka ke RAM atau ASAL, atau memuat turun PNG. **Ruang Output SPSS dan AMOS** (folder Dapatan, Metodologi dan Perbincangan artikel empirikal): jadual ditampal terus daripada SPSS, AMOS atau Excel, rajah dimuat naik atau ditampal; setiap output berlabel dan berkategori dengan senarai semak, boleh disisip ke RAM atau ASAL dengan kapsyen, dihantar kepada agen (teks jadual dan imej), dan meter Angka dan output menyemak angka dalam ASAL terhadap output. Setiap panggilan agen memaparkan anggaran token masuk dan had token keluar berserta asas kiraannya (v1.31.1: bajet jawapan mengikut panjang yang diminta, ditambah ruang berfikir model), dan dicaj kepada akaun Anthropic pemilik. Simpanan: `meta/pandu_<id>` (tetapan, peta folder, PRISMA), `meta/pandu_<id>__<folder>` (pilihan sumber, jawapan, log agen), `meta/pandu_<id>__output`, `meta/pandu_gaya` (peraturan gaya), berserta salinan tempatan.
- **Folder Kajian Literatur (Literature Review) pilihan** (Pandu Tulis; v1.32.0): artikel empirikal dan konseptual sudah mempunyai folder ini, begitu juga artikel contoh terbina bagi ulasan sistematik, meta-analisis dan bibliometrik. Ulasan skop tidak mempunyainya kerana artikel contohnya (Karsikas et al., 2022) dan senarai semak PRISMA-ScR (Tricco et al., 2018, https://doi.org/10.7326/M18-0850; butir 3 Rationale dan butir 4 Objectives, tiada butir Literature Review) meletakkan latar literatur di dalam Pendahuluan. Pemilih **Folder Kajian Literatur** di bar atas Pandu Tulis kini menambah folder itu selepas Pendahuluan bagi mana-mana struktur yang belum mempunyainya (kecuali ulasan naratif): seksyennya dicipta terus dalam manuskrip, atau seksyen sedia ada bertajuk Literature Review, Kajian Literatur, Conceptual Background dan seumpamanya dipadankan; teks sedia ada tidak diubah. Bagi artikel ulasan, panduan folder ini khusus: takrif konsep, lensa teori, sintesis kajian berkaitan, ulasan terdahulu dan batasnya, serta rumusan jurang, dengan lima soalan panduan dan tujuh kriteria semakan; ia menulis apa yang sudah diketahui sebelum ulasan dijalankan dan tidak melaporkan dapatan ulasan. Sasaran folder ialah 12 hingga 18 peratus daripada sasaran jumlah, dan sasaran folder lain dikecilkan sekadar itu. Agen Pendahuluan dan agen folder ini dimaklumkan tentang sempadan isi masing-masing. Lalai: Ada bagi artikel yang foldernya baru disediakan; artikel yang sudah disediakan sebelum versi ini kekal seperti asal sehingga pemilik memilih Ada. Memilih Tiada hanya mengeluarkan folder daripada Pandu Tulis; seksyennya tidak dipadam.

- **Ruang PRISMA dalam Metodologi sahaja, rentetan carian dan Ruang Rajah Statistik (pilihan)** (Pandu Tulis; v1.33.0): Ruang PRISMA 2020 dipaparkan dalam folder Metodologi sahaja; agen folder Dapatan tetap menerima angka yang sama supaya teks selaras. Ruang PRISMA mendapat tiga tambahan. Pertama, butang "Mohon Prof Dr Claude cadangkan rentetan carian" meminta agen mencadangkan rentetan khusus bagi setiap pangkalan data berdasarkan tajuk, pemboleh ubah dan artikel sumber. Rentetan diisi hanya pada entri yang masih kosong, tarikh carian dan bilangan rekod dibiarkan kosong, dan entri ditanda "Belum dijalankan" sehingga kedua-duanya diisi. Agen penulisan diberitahu supaya tidak menulis rentetan yang belum dijalankan sebagai carian yang sudah dibuat, dan cadangan penuh (jadual konsep, langkah, artikel untuk menguji rentetan) disisip ke RAM Metodologi. Kedua, "Panduan pengisian" memaparkan lapan langkah pengisian kotak demi kotak dengan status semasa, tanpa token. Ketiga, baris "Kaedah lain (nyatakan)" membolehkan rekod yang ditemui melalui kaedah selain pangkalan data, termasuk pembantu AI, dilaporkan dengan nama alatnya. Sistem dan agen tidak mengisi angka aliran. Folder Dapatan pula mendapat Ruang Rajah Statistik (pilihan): graf palang menegak atau mendatar, carta pai dan graf garis yang dibina daripada medan sebenar artikel sumber (tahun, negara, reka bentuk dan lain-lain) atau daripada data yang ditaip sendiri. Rajah boleh disisip ke RAM atau ASAL dan dimuat turun sebagai PNG, dan jadual kekerapannya boleh disisip ke RAM. Modul baharu `mod/rajah.js`; pilihan rajah disimpan pada `P.t.rajah`.
- **Larian carian sebenar oleh sistem dan "Mohon Prof Dr Claude janakan Jadual PRISMA"** (Ruang PRISMA; v1.34.0): setiap entri pangkalan data dipadankan dengan satu "penyambung" mengikut namanya, tanpa terikat kepada mana-mana dua pangkalan data. Bagi pangkalan data yang mempunyai API rasmi terbuka (ERIC, OpenAlex, DOAJ dan PubMed), butang "Jalankan dalam ... (sistem)" menghantar rentetan terus kepada API itu dari pelayar, lalu mengisi bilangan rekod sebenar dan tarikh hari ini; had tahun, berwasit dan jenis dokumen ditulis ke dalam rentetan mengikut sintaks API supaya rentetan yang dicetak sama dengan yang dijalankan. Jika hasil muat dalam satu halaman API, senarai tajuk disimpan ("Lihat N rekod") dan dipadankan dengan artikel sumber. Nota larian memberi amaran apabila rentetan atau bilangan diubah selepas larian, dan agen penulisan hanya diberitahu "dijalankan oleh sistem" selagi kedua-duanya sepadan. Pangkalan data berlangganan atau tanpa API terbuka (Scopus, Web of Science, EBSCOhost, MyJurnal dan lain-lain) tidak dapat dicapai oleh sistem: bilangannya kekal diisi oleh pengguna, dengan pembantu "Salin rentetan" dan "Tarikh hari ini". Butang "Mohon Prof Dr Claude janakan Jadual PRISMA" menjalankan semua entri yang boleh dijalankan, mengisi baris "Kaedah lain (nyatakan)" daripada senarai artikel sumber sebenar jika masih kosong, melukis rajah dan menyenaraikan kotak saringan yang masih perlu diisi. Sistem tidak menganggar atau mereka sebarang angka, dan tiada token digunakan. Peraturan gaya "paling banyak N pangkalan data" kini nota panduan sahaja, bukan isu. Pangkalan data baharu ditambah sebagai satu objek dalam `PENYAMBUNG` (`mod/prisma.js`).

- **Jadual kriteria kelayakan yang tetap** (Ruang PRISMA; v1.36.0): setiap artikel ulasan mendapat Jadual 1 dengan lapan baris tetap (Population, Concept, Context, reka bentuk kajian, jenis penerbitan, tahun penerbitan, bahasa, capaian), disimpan pada `P.t.prisma.kriteria`; label mengikut bahasa manuskrip kecuali diubah, dan baris boleh ditambah, dibuang atau dipulihkan. "Sisip Jadual kriteria ke RAM" dan "Sisip Jadual kriteria ke ASAL" menghasilkan jadual berformat APA (nombor tebal, tajuk condong); satu baris status menyatakan sama ada jadual itu sudah ada dalam seksyen Metodologi, supaya teks tidak merujuk jadual yang tidak wujud. Baris yang diisi oleh agen ditanda sebagai cadangan sehingga disunting, dan satu baris hanya diisi daripada rentetan apabila kedua-dua selnya kosong. - **Saringan rekod** (Ruang PRISMA; v1.37.0; `mod/saring.js`): angka aliran PRISMA dihasilkan daripada keputusan bagi setiap rekod, bukan ditaip. Langkah 1 menjalankan semula rentetan yang direkodkan, menarik kesemua rekod melalui kaedah `halaman()` setiap penyambung (ERIC, Scopus dengan kunci pengguna, OpenAlex, DOAJ, PubMed, Europe PMC), membuang pendua mengikut DOI dan tajuk, dan melengkapkan abstrak yang tidak dibekalkan oleh API (contohnya Scopus) daripada OpenAlex mengikut DOI tanpa menghantar maklumat pengguna. Fail kedua memuatkan 1,172 judul daripada helaian Discontinued Titles (1,000 Discontinuation dan 172 Journal change policy), disatukan dengan baris bertanda Discontinued by Scopus dalam helaian Sources (1,810 ISSN, 851 nama panjang), berserta tahun liputan akhir. Edisi September 2026 tiada lajur SJR. Sejak v1.30.2 kuartil diambil daripada lajur SJR Best Quartile fail "Download data" SCImago Journal & Country Rank (edisi 2025; halaman Journal Rankings, semua bidang dan semua negara), dipadankan mengikut ISSN, dan `meta.kuartil_rasmi` ditandakan; 704 jurnal aktif tiada kuartil dalam edisi itu. Sehingga v1.30.1 kuartil dibawa mengikut ISSN daripada anggaran SJR 2023 dalam binaan November 2024. Untuk mengemas kini, muat turun fail Excel senarai Scopus terkini yang dipautkan pada halaman https://www.elsevier.com/products/scopus/content/content-policy-and-selection (dikemas kini setiap bulan) dan jalankan `python3 tools/bina_scopus.py <fail.xlsx> data/scopus.json data/scopus_henti.json --scimago <fail CSV SCImago>` (atau `--kuartil <scopus.json terdahulu>` jika fail SCImago tiada, maka kuartil lama dibawa); fail Excel dan fail CSV itu tidak disimpan dalam repositori. Fail SCImago dimuat turun sendiri melalui pelayar (https://www.scimagojr.com/journalrank.php, butang Download data), kerana laman itu menyekat muat turun automatik. Sumber kuartil: SCImago. (t.t.). SJR: SCImago Journal & Country Rank [Portal]. https://www.scimagojr.com Senarai liputan dihentikan v1.30.0 (296 judul yang dibaca daripada salinan PDF status Ogos 2026) disimpan dalam `tools/arkib/` sebagai rekod: kesemua 445 ISSN-nya terdapat dalam helaian rasmi September 2026.
- **Satu sumber untuk semua peranti**: setiap PDF, sama ada dimuat naik di Windows, Android atau pelayar, disimpan dalam folder "Repositori SLR" di Google Drive dan rekodnya dalam Firestore; peranti lain membacanya terus dari situ. "Simpan ke Drive" mencuba tiga laluan mengikut urutan: salinan OpenAlex (`content.openalex.org`, kira-kira 100 fail sehari dengan kunci API percuma), pautan penerbit (jika penerbit membenarkan), dan akhirnya langkah manual (Buka PDF, simpan, kemudian Pilih fail PDF atau seret ke kad). Di Android, fail PDF juga boleh dikongsi terus ke aplikasi (Kongsi > Repositori SLR); fail yang dikongsi dimuat naik ke Drive dan, jika DOI dalam PDF sepadan dengan cadangan hari ini, dipautkan ke kad itu secara automatik.
- **Peta Ayat**: taip istilah; semua ayat yang mengandunginya daripada semua PDF yang diindeks dikumpulkan, dikelompokkan mengikut pola istilah yang sama, dengan sumber (Bil., penulis, tahun, muka surat), butang Buka (flipbook pada muka surat itu), Salin dengan sitasi dan Eksport CSV. "Frasa tepat" mencari urutan perkataan yang sama.
- **Tetapan**: kunci API OpenAlex (percuma, disyorkan), kunci API Anthropic dan model untuk "Mohon Prof Dr Claude isikan", pilihan Agen Bahasa selepas isian (v1.31.0), kedalaman berfikir model (v1.31.1), serta profil kajian. Tetapan disimpan dalam Firestore (`meta/tetapan`) dan salinan tempatan peranti; jika Firestore menolak, aplikasi memberitahu bahawa tetapan hanya tersimpan pada peranti itu. Tanpa kunci, bajet awam ialah kira-kira 100 carian atau 10 muat turun sehari yang dikongsi semua pengguna pada alamat IP yang sama; dengan kunci, 1,000 carian atau 100 muat turun sehari.
